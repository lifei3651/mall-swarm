# 灵启商城 1.0.3 发版报告

发布时间：2026-08-03 16:57（Asia/Shanghai）  
发布环境：`https://lingqimall.com`  
发布状态：成功

## 本次已发布

### 安全请求稳定性

1. 修复商城前端和管理后台偶发“页面安全组件已更新，请刷新页面后重试”。
2. 前端获取一次性加密挑战时增加时间戳并禁止缓存，避免浏览器或代理重复使用旧挑战。
3. 加密请求头兼容新版 Axios 的请求头对象，不再因请求头写入方式不同而丢失。
4. 后端优先从原始 HTTP 请求读取加密标识和加密密钥，避免请求体转换包装后读取不到请求头。
5. 加密挑战接口增加 `Cache-Control: no-store` 和 `Expires: 0`，继续保留一次性挑战、防重放和 RSA-OAEP + AES-256-GCM 加密。

### 登录与手机号校验

1. 未登录进入购物车、个人中心等受保护页面时，统一提示“请先登录”，随后跳转登录页并保留原目标地址。
2. 登录会话过期统一清理本地会话，提示“登录状态已失效，请重新登录”并返回登录页。
3. 商城地址、结算、转账、登录、注册、找回密码、修改登录密码和交易密码等手机号字段统一执行中国大陆 `1[3-9]` 开头的11位格式校验。
4. 后台新增会员、修改手机号、导入和迁移等入口同步执行相同校验；后端再次校验，不能通过绕过前端提交错误号码。
5. 手机号重复注册改为“该手机号已注册，请直接登录或使用其他手机号”；用户名重复改为“该用户名已被使用，请更换用户名”；手机号被其他账号占用时给出单独提示。

### 会员标识清理

1. 删除商城和后台对 `M000000xx` 会员编号的生成、解析、查询和展示，不再把数据库主键包装成业务会员编号。
2. 会员查询、展示和导出统一使用“登录账号”，手机号仍作为独立联系方式和可选登录方式。
3. 数据库内部数值主键和 `user_id` 继续保留，仅作为表关联键，不展示给客户，也不作为后台业务查询条件。
4. 两个内部资金归集账户改用固定系统账号 `SYSTEM_REMAINDER`、`SYSTEM_PRODUCT_COST` 定位，不使用 M 编号，不出现在普通会员列表和关系树中。

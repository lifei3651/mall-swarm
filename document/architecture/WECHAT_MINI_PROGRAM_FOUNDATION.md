# 微信小程序通用基座与客户定制边界

更新时间：2026-08-30

## 产品结论

微信小程序应当作为商城基座的一种独立公开前端长期维护，微信登录与手机号快捷注册属于所有客户都会用到的通用能力；客户主体、微信账号、支付商户、订阅模板和奖金制度属于客户独立项目，不能写进公共基座。

本地候选版已经完成“可安全派生的小程序公共底座”和微信支付API v3程序闭环，但不代表任何客户的小程序已经通过微信审核、绑定商户号或可以正式收款。真实资金能力必须在客户独立项目中使用客户自己的资料启用并验收。

## 当前流程

```mermaid
flowchart LR
    A[用户打开客户小程序] --> B[浏览商品/分类]
    B --> C{是否需要登录}
    C -->|老用户| D[用户同意隐私说明]
    D --> E[微信登录临时代码]
    E --> F[服务器换取微信身份]
    F --> G[匹配已有商城账号并创建小程序会话]
    C -->|首次使用| H[用户主动点击手机号一键注册]
    H --> I[服务器向微信核验手机号]
    I --> J[创建或匹配商城账号]
    J --> K{入口是否带合法邀请码}
    K -->|是| L[注册事务内一次性绑定邀请关系]
    K -->|否| M[保持普通购物账号]
    L --> N[创建小程序会话]
    M --> N
```

- 邀请关系只记录“谁邀请了谁”，不会在公开小程序展示奖金或自动宣传推广收益。
- 已经绑定的微信身份再次登录不重复索取手机号。
- 微信临时登录码和手机号授权码只交给服务器使用；`session_key`、AppSecret、OpenID、UnionID均不返回前端。
- OpenID、UnionID在数据库中加密保存，并使用不可逆摘要进行精确查找。

## 能力归属

| 能力 | 公共基座 | 客户独立项目 |
| --- | --- | --- |
| 原生小程序页面与网络层 | 统一维护 | 选择品牌和客户UI增量 |
| 微信登录、手机号快捷注册 | 统一流程和安全规则 | 提供自己的AppID/AppSecret并联调 |
| 扫码邀请码 | 统一解析，首次注册事务内一次绑定 | 决定推广资格方式和客户制度 |
| 商品、购物车、订单读取 | 复用商城公共接口 | 配置真实商品、库存、运费和售后资料 |
| 微信支付/退款 | 统一维护预下单、`wx.requestPayment`、查单、验签回调、关单和原路退款程序 | 每客户独立商户号、证书、公钥、回调、权限和真实资金验收 |
| 订阅消息 | 只保留关闭状态 | 每客户独立模板、场景授权和送达验收 |
| 奖金、等级、复购、报单 | 不写进公开小程序，不固定公式 | 每个客户单独开发、测试和部署 |
| 发布 | 不使用基座测试AppID发布 | 每客户独立备案、审核、版本和服务器 |

## 当前已完成

- 独立原生小程序工程：主页、分类、商品详情、购物车、登录、个人中心、订单列表。
- 微信服务端登录、手机号核验、账号创建/匹配、加密身份映射和隐私同意审计。
- 老用户免重复手机号授权；新用户必须主动点击微信手机号授权，拒绝时不会注册。
- 邀请码随扫码入口暂存，只在首次注册时一次性处理；普通入口不会凭空绑定上级。
- 客户级总开关、手机号开关、配置完整性检查、独立限流、敏感响应禁止缓存。
- 客户项目派生时自动保留小程序源码并重置为不可发布的安全地址。
- 新增第31项幂等数据库迁移，只增加微信身份映射表。
- 新增购物车结算、收货地址维护和待支付订单继续支付；客户支付配置未启用时，结算在创建订单前停止。
- 接入微信支付官方Java SDK与API v3小程序支付：服务端按真实订单金额和已绑定OpenID预下单，小程序只使用服务端签发参数调起支付，前端成功提示不能直接修改订单。
- 支付成功以验签解密后的微信回调或服务端主动查单为准，并校验AppID、商户号、商户订单号、金额、币种和OpenID；重复通知按本地订单状态幂等处理。
- 用户取消或系统超时关闭待支付订单后，在本地事务提交成功后关闭微信订单；若出现关单与支付并发，迟到支付会使用固定幂等退款号原路退回。
- 售后退款支持微信异步受理与签名退款通知，退款单号、原支付单号、原订单金额、退款金额、币种和售后状态全部匹配后才完成本地售后。
- 大额支付短信风控同时覆盖H5和小程序，业务类型与接收手机号由服务端固定，前端不能改发到其他号码。

## 基座默认关闭与尚未实现

- 微信支付程序已完成，但基座默认`WECHAT_PAY_ENABLED=false`；客户资料、权限和真实联调未完成时，小程序结算不会创建无法付款的订单。
- 微信支付“分账”不是普通支付/退款的一部分，本版没有实现，也不会把客户的二级分销奖金直接等同为微信支付分账。
- 小程序订阅消息、发货信息同步和微信购物订单详情回跳程序已接入；客户真实模板、订单中心协议、详情路径、支付商户资料和运行开关仍需逐客户配置并完成真机验收，基座默认关闭真实外部投递与支付。
- 没有把基座生产AppID、AppSecret、商户号、证书或真实域名写入仓库。
- 没有把团队中心、奖金说明、提现或余额互转放进公开小程序。

## 客户上线资料与验收

客户至少需要提供：已认证的小程序主体与AppID、AppSecret、管理员协作权限、备案和类目资料、隐私政策、HTTPS业务域名；若要收款，还需自己的微信支付商户号、商户API证书序列号与私钥、微信支付公钥ID与公钥、API v3密钥、支付/退款回调域名，并完成AppID与商户号绑定及小程序支付权限开通。

正式交付前必须在微信开发者工具和真实手机验证：同意/拒绝隐私、同意/拒绝手机号、老账号匹配、新账号注册、重复登录、扫码邀请、登录失效、弱网、商品/库存变化；支付接入后还要验证真实小额支付、微信购物订单找回及详情回跳、用户取消、支付密码或余额不足、回调验签、重复通知、主动查单、超时关单、支付关单竞态、发货信息同步、全额/部分退款和重复退款通知。微信后台订单中心协议与路径配置、审核、备案、发货信息管理要求和真机资金UAT不能用本地自动化替代。

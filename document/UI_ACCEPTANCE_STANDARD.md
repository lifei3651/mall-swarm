# 商城界面统一验收规范

2026-09-13，依据用户多次确认的微信式简洁分组、通栏对齐要求。适用于小程序、H5/App网页和后台对应业务表单；不更换客户主题，不删减交易、身份或资金校验。

## 每轮必须检查

1. 页面以导航标题、通栏内容组、次级说明组织；不重复堆叠大标题。不在通栏内容间插入短小居中的表单卡。
2. 选择行有明确标签、当前值、选择箭头；长值可收缩或换行；无可选数据时显示空态，不打开只有一个“无”的菜单。错误、加载中与确实为空必须区分。
3. 小程序普通选择保留微信原生选择器，H5保留可键盘操作的原生选择控件；展开方式可按平台不同，行的层级与对齐一致。
4. 表单主操作通栏；取消/关闭是固定触达尺寸的次操作，与标题同行且不抢宽度。图标按钮必须核对实际宽高，不能只检验样式源码。
5. 同组行的左右边距、字号、圆角、行高一致；短操作不被默认按钮样式拉宽，长标题和金额不挤压旁边的按钮。
6. 状态筛选的末项必须可达，不露灰色滚动轨道；必要横滑保留，不用全局裁剪隐藏内容。
7. 成功以页面更新为主，不弹“知道了”；错误、删除、付款、授权等必要提醒/确认保留。早期文档要求“每次成功弹窗”已被用户后续要求取代。
8. 每次新增或修改控件必须搜索全项目同类控件，不只修截图的一处；验收包含默认、有数据、空数据、错误、加载、长内容、禁用及弹层。
9. 至少核对320与390宽度；记录代码检查、H5浏览器、小程序模拟器、真机分别完成了什么，不互相替代。

## 本轮检查入口

小程序全部29个注册页面为基础清单，账户页各编辑模式、登录各模式、工单创建、地址编辑、售后原因/快递、结算备注/选券、商品规格/保障弹层属于追加状态。后台使用桌面表格/表单规范，不将后台强行改成手机列表。

本轮证据与逐页结果见 `qa/2026-09-13-ui-consistency/README.md`。修改只在开发源码完成，未发版的结果不得写成手机已生效。

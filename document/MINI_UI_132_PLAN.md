# 小程序体验重构（1.0.132 候选）

2026-09-06，依据客户本轮九张截图。仅开发、验证；不自动部署、不上传腾讯、不提交审核。

| 范围 | 设计及验收标准 |
| --- | --- |
| 我的 | 保留统一登录入口；本人会员等级从服务端读取；订单标题细分隔线；常用服务为图标宫格，余额入口不再错位 |
| 余额 | 可提现余额、已发放奖金、待发放奖金分开；奖金以现有结算状态为准，不把充值、转入视为奖金；提现按钮仅写“提现” |
| 提现 | 使用原有实名、支付密码、短信、幂等、风控和到账确认规则；条件不足明确说明，不假装成功 |
| 资料 | 头像与昵称编辑紧凑、清晰；区分上传失败和上传成功但预览失败；不把所有错误笼统说成网络问题 |
| 提示 | 操作失败、校验失败与操作完成用需要确认的显眼弹窗；页面保留必要的就地错误与重试，不只在底部提示；不显示密钥、验证码或底层错误堆栈 |
| 装修 | 分类版切换自动预览分类页；紧凑商品不使用三列微小卡片；直播/新品只保留一个展示位置配置入口，保留原有内容 |
| 验证 | 独立的小程序测试、后台测试、原生编译/页面截图；不能以 H5 测试代替真机授权、真实提现 |

## 不可回退的产品约束

- 客户明确要求所有操作提示显眼、精准、弹窗确认。以后新增流程必须遵守。
- 小程序展示本人等级和本人资金，不开放团队树、他人收益或团队后台接口。
- 待发放金额不是可提现金额；售后期结束也不等于已发放，必须结算实际成功。
- 不虚构已发放、不从“当前余额”推算累计奖金；未知数据展示“暂不可用”，不展示假零。
- 本次不改变 H5 的账户、邀请码、奖金和提现业务规则。

## 当前发现

- 钱包入口使用 menu-label，而其他入口使用伸展的 menu-name，导致箭头错位。
- 分类 A/B/C 控制分类页，但装修预览留在首页，导致选择结果不可见。
- 紧凑版的后台预览使用三列，文字和商品图过小。
- 头像上传错误丢弃了微信返回原因，统一误报网络/域名；资料操作提示放在表单底部。
- 头像实际真机失败原因仍需结合返回错误或平台域名配置验证，不能直接归因部署。

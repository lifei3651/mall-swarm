# 灵启商城多商户业务设计

适用版本：`1.0.56 app-h5-split` 本地候选

## 一、定位

多商户是同一商城核心上的可选模块，不再复制第三套代码。未启用时所有商品继续是平台自营；只有明确绑定商户的商品才产生商户货款。

当前阶段采用平台运营管理模式：平台后台维护商户、商品归属、提现申请、发票和人工打款。独立商户登录、自助上架、自助发货和自助申请提现不在本阶段范围，避免在没有完整商户身份与数据隔离前开放高风险入口。

## 二、订单与货款

1. 一个商品最多绑定一个商户。
2. 一张订单只能包含同一商户的商品，或只包含平台自营商品。
3. 下单时保存商户、成本单价和奖金模式快照，后续修改商品成本不影响历史订单。
4. 应结货款＝订单成本单价快照 × 有效数量。
5. 平台服务费默认为 0，不从商户货款中自动抽成。
6. 支付成功后货款进入待结算；确认收货、售后窗口结束且没有进行中售后后进入可提现。
7. 退款按原订单成本快照和退款数量冲回。已经打款后退款而余额不足时形成商户欠款，未来货款先抵欠款。

商户结算成本不是普通商品资料。平台后台修改商户、商品结算成本或SKU结算成本时，必须同时具有商品管理和财务管理权限，并填写修改原因；系统保存修改前后值、操作人和时间。未来独立商户端只能提交成本变更申请，不能直接改写平台审核后的结算成本。平台自营商品的参考成本仍只用于利润统计。

## 三、提现、发票与打款

状态流为：

`已提交 → 待收发票/待打款 → 已打款`

财务也可在打款前驳回。没有退款欠款时，申请金额完整解冻并退回可提现余额；冻结期间已经产生退款欠款时，先抵欠款，剩余部分再退回可提现余额。

已打款或已驳回的申请不能再次打款或再次驳回；发票仍为待收状态时禁止确认打款。

系统记录申请金额、应开票金额、已收票金额、发票状态、调整金额、调整原因、实际打款金额、银行流水号和凭证地址。不增加“扣税”或“税率”字段：系统不是税务判断主体，任何差额使用通用调整金额并要求说明原因。负数调整会永久减少本次应付，不会退回可提现余额；冻结后出现退款欠款时必须优先用调整差额抵欠款。

## 四、销售区与团队奖金

| 销售区 | 面向对象 | 团队奖金建议 |
| --- | --- | --- |
| 普通商城 | 普通购物用户、App、小程序 | 默认不发团队奖 |
| 复购区 | 已满足复购资格的团队用户 | 可按标准规则或客户定制 |
| 报单区 | 团队业务场景 | 可按标准规则或客户定制 |

奖金模式：

- `INHERIT`：兼容已有商品和历史规则。
- `NONE`：该商品不产生团队奖金。
- `STANDARD`：使用当前标准奖金引擎。
- `CUSTOM`：预留客户定制；没有完成规则、冲销和回归测试前拒绝下单。

标准团队奖金商品只能进入复购区或报单区，不能同时作为普通商城商品销售。商户成本结算和团队奖金是两本账：商户收到成本货款，团队奖金从订单奖金规则独立计算和冲销。

同一订单同时包含发团队奖和不发团队奖的商品时，只统计允许发奖的商品数量与金额；整单优惠按各商品金额比例分摊后再计算奖金基数，不能把不发奖商品的优惠全部扣到发奖商品上。

## 五、权限与审计

- 商户资料使用商品管理权限。
- 货款账户、明细和提现查询使用财务只读权限。
- 提现申请、发票审核、打款和驳回使用财务管理权限。
- 所有商户、账户、结算和提现查询按租户隔离。
- 打款和调整保存后台操作人；非零调整必须有原因。
- 商户归属、商品结算成本和SKU结算成本的新增或修改必须同时具有财务管理权限并填写原因，操作日志保存前后值。
- 当前不开放商户账号。未来开放时必须增加商户身份、会话中的商户编号、服务端逐条归属校验和跨商户越权测试。

## 六、上线边界

- 发布前执行并登记 `V202608171600__multi_merchant_foundation.sql`。
- 先在隔离环境创建测试商户，跑通“商品绑定 → 下单支付 → 收货 → 售后窗口结束 → 可提现 → 发票审核 → 打款 → 部分退款/欠款抵扣”。
- 真实支付、真实退款、客户合同、发票和财务打款仍需客户共同验收。
- 本设计不改变现有平台自营商品和历史订单，也不自动启用任何客户定制奖金制度。

# 灵启商城多商户业务设计

适用版本：`1.0.56 app-h5-split` 本地候选

## 一、定位

多商户是同一商城核心上的可选模块，不再复制第三套代码。未启用时所有商品继续是平台自营；只有明确绑定商户的商品才产生商户货款。

当前阶段复用同一管理后台作为商户工作台：平台为后台账号绑定商户后，该账号只能查看和维护本商户商品，并查看本商户订单、售后、货款、保证金、提现记录及发起提现申请；不能进入平台财务、会员、奖金、审核或系统配置，也不能审核发票、确认打款或冻结保证金。履约状态为 `ENABLED` 时，商户可对自己的子订单发货并处理正常客户售后；切换为 `PLATFORM_ONLY` 或 `DISABLED` 后仍可查看历史订单和填写客服备注，但发货、批量导入及售后处理由平台接管。

## 二、订单与货款

1. 一个商品最多绑定一个商户。
2. 一次购物车结算可以包含平台自营和多个商户商品；系统创建一张支付父交易，并按平台/商户拆成多张履约子订单。
3. 下单时保存商户、结算单价、结算等待天数和奖金模式快照，后续修改商品结算价或等待天数不影响历史订单。
4. 应结货款＝订单结算价快照 × 有效数量。
5. 平台服务费默认为 0，不从商户货款中自动抽成。
6. 支付成功后货款进入待结算；预计可结算时间为“确认收货时间与售后截止时间的较晚者＋订单等待天数”，到期且没有进行中售后后进入可提现。
7. 退款按原订单结算价快照和退款数量冲回。已经打款后退款而余额不足时形成商户欠款，未来货款先抵欠款。
8. 父交易只负责一次支付和汇总金额；发货、收货、售后、退款、货款和奖金都按商户子订单独立处理。待付款时取消任一子单会取消整笔联合交易，付款后不能跨商户合并履约。

商户结算价不是普通商品资料。商户负责填写商品资料、销售价和结算价，保存后商品保持下架；提交审核后，平台审核页明确展示销售价、结算价及各SKU价格，通过后自动上架。已经上架的商户商品不能直接编辑，必须先下架；任何编辑会回到草稿并要求重新审核。平台人员直接修改商户归属或结算价时仍需财务管理权限和修改原因。平台自营商品的参考成本仍只用于利润统计。

提交审核时，系统同时校验商户仍处于启用状态、商品及启用SKU的销售价和结算价均大于0，并拒绝结算价高于对应销售价的商品，避免明显倒挂价格进入人工审核或前端商城。

审核状态为：`草稿 DRAFT → 待审核 PENDING → 已通过 APPROVED / 已驳回 REJECTED`。同一商品每次提交生成独立版本和完整快照，重复处理已完成审核会被拒绝。仅“已通过”商品允许上架；新订单使用当前审核通过版本，历史订单继续使用原订单项快照。

## 三、提现、发票与打款

每个商户设置0～365天默认结算等待；商品可跟随商户默认，也可为高风险单品单独设置例如30天。平台设置的单品等待属于审核结算条款，商户账号不能自行更改；确认收货后预计可结算时间固化，不因后续修改配置影响历史订单。

状态流为：

`已提交 → 待收发票/待打款 → 已打款`

财务也可在打款前驳回。没有退款欠款时，申请金额完整解冻并退回可提现余额；冻结期间已经产生退款欠款时，先抵欠款，剩余部分再退回可提现余额。

已打款或已驳回的申请不能再次打款或再次驳回；发票仍为待收状态时禁止确认打款。

系统记录申请金额、应开票金额、已收票金额、发票状态、调整金额、调整原因、实际打款金额、银行流水号和凭证地址。不增加“扣税”或“税率”字段：系统不是税务判断主体，任何差额使用通用调整金额并要求说明原因。负数调整会永久减少本次应付，不会退回可提现余额；冻结后出现退款欠款时必须优先用调整差额抵欠款。

商户保证金和提现冻结是两个独立余额。平台可从商户可提现余额冻结保证金，解冻时先抵退款欠款，剩余部分返回可提现；每次冻结/解冻使用唯一操作号并保存金额、原因、操作后余额和操作人，重复请求不会重复扣款。

平台也可在确认线下到账后直接登记保证金，不占用商户可提现货款。每个商户有应缴保证金目标，未缴足时禁止提交/通过商品审核及申请提现。退款冲回时先扣可提现货款，再扣保证金，仍不足才形成商户欠款。

提现前必须具备已签署合同、完整经营主体和银行收款资料。每次申请携带持久请求号，数据库只允许同商户同请求号生成一笔申请；网络超时重试返回原记录，不会再次冻结。申请记录保存商户资料版本及当时的主体、户名、银行、账号快照，后续修改商户资料不回写历史申请。

## 四、销售区与团队奖金

| 销售区 | 面向对象 | 团队奖金建议 |
| --- | --- | --- |
| 普通商城 | 普通购物用户、App、小程序 | 默认不发团队奖 |
| 复购区 | 已满足复购资格的团队用户 | 可按标准规则或客户定制 |
| 报单区 | 团队业务场景 | 可按标准规则或客户定制 |

奖金模式：

- `INHERIT`：兼容已有商品和历史规则。
- `NONE`：该商品不产生团队奖金。
- `STANDARD`：使用当前标准奖金引擎。
- `CUSTOM`：预留客户定制；没有完成规则、冲销和回归测试前拒绝下单。

标准团队奖金商品只能进入复购区或报单区，不能同时作为普通商城商品销售。商户货款结算和团队奖金是两本账：商户收到按结算价计算的货款，团队奖金从订单奖金规则独立计算和冲销。

同一订单同时包含发团队奖和不发团队奖的商品时，只统计允许发奖的商品数量与金额；整单优惠按各商品金额比例分摊后再计算奖金基数，不能把不发奖商品的优惠全部扣到发奖商品上。

## 五、权限与审计

- 商户资料使用商品管理权限。
- 货款账户、明细和提现查询使用财务只读权限。
- 商户工作台的提现申请、平台的发票审核、打款和驳回都使用财务管理权限；服务端再按账号是否绑定商户限制实际可执行动作。
- 所有商户、账户、结算和提现查询按租户隔离。
- 打款和调整保存后台操作人；非零调整必须有原因。
- `shop:product-review` 为独立商品审核权限，商户工作台账号不能拥有该权限。
- 后台账号可绑定 `merchant_id`；绑定后权限固定在基础查看、商品管理和本商户货款范围，服务端对商品、账户、明细、保证金和提现逐条校验商户归属，并只允许商户自行提交本商户提现。
- 商户填写的销售价和结算价必须经平台审核才会生效上架；审核提交、通过和驳回均记录版本、快照、操作人和说明。
- 平台直接变更商户归属或结算价仍要求财务管理权限和原因，操作日志保存前后值。
- 商户服务地址按“平台私有、平台共享、商户私有”隔离。商户只读平台明确共享地址，只能维护本商户地址，商品发货和退货地址在服务层再次校验归属。
- 商户订单列表、单笔发货、批量物流导入和售后处理均以后端会话中的 `merchant_id` 校验归属；Excel 中填写其他商户订单号会逐行拒绝。父交易汇总、平台取消、后台人工退款和团队奖金仅允许平台账号操作。
- 停用商户会事务内下架全部商户商品，公开商品查询、详情、库存扣减和下单仍分别校验商户启用状态；重新启用不会自动恢复商品上架。
- 商户默认结算天数变化时，只将跟随默认值的商品和对应待审核单退回重新审核；设置单品覆盖天数的商品不被误退回。

- 再执行并登记 `V202608171930__merchant_product_review_workflow.sql`，增加商户账号绑定、商品审核状态和审核版本快照。
- 最后执行并登记 `V202608181030__merchant_settlement_cycle_and_deposit.sql`，增加默认/单品结算等待、固化到期时间、独立保证金和商户货款工作台权限。
- 执行并登记 `V202608182245__multi_merchant_parent_trade.sql`，增加交易父单及子订单联合支付字段；该迁移必须早于支持跨商户结算的后端与前端程序。
- 先在隔离环境创建测试商户，跑通“商品绑定 → 下单支付 → 收货 → 售后窗口结束 → 可提现 → 发票审核 → 打款 → 部分退款/欠款抵扣”。
- 真实支付、真实退款、客户合同、发票和财务打款仍需客户共同验收。
- 本设计不改变现有平台自营商品和历史订单，也不自动启用任何客户定制奖金制度。

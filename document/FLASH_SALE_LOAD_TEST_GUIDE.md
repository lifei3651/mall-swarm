# 秒杀并发验收执行说明

秒杀压测会真实创建待付款订单，只允许在隔离测试环境执行。正式商城、客户生产库和包含真实资金的账号禁止直接使用本工具。

## 验收前准备

1. 在后台开启测试租户的秒杀总开关，建立一场当前有效的测试活动，并记录活动库存。
2. 准备多名独立测试会员，均需已设置支付密码、配置有效收货地址。
3. 每个会员登录后取得一次仅用于本轮测试的 `shop_session`，一行一个写入本机临时文件。该文件不得加入 Git、日志或聊天记录。
4. 准备一个订单 JSON，格式与 `ShopOrderSubmitDTO` 一致，商品、SKU、数量、地址和活动必须互相匹配。
5. 发布前记录活动库存、SKU库存、商品库存、订单数和秒杀预约数，测试后再次核对。

## 执行

```bash
python3 scripts/flash-sale-concurrency-check.py \
  --base https://隔离测试域名 \
  --activity-id 活动ID \
  --payload /本机临时目录/flash-order.json \
  --sessions /本机临时目录/test-sessions.txt \
  --expected-stock 活动开始前库存 \
  --repeat-per-member 2 \
  --concurrency 40 \
  --confirm-write-test YES
```

工具只输出会员数量、请求数量、成功订单数、拒绝原因、延迟和验收结论，不打印会话内容。每位会员同时提交两次，用于验证同场秒杀只能成功一单。

## 通过标准

- 每位会员成功订单数不超过 1；
- 成功订单号不存在重复；
- 成功总量不超过活动开始前库存；
- 无网络层或服务崩溃错误；
- 活动库存、SKU库存、商品库存的减少量与成功订单数量一致；
- 取消或超时关闭待付款订单后，库存和会员资格按规则恢复；
- Redis临时不可用的单独演练仍不超卖，并能产生明确告警；
- 重复支付通知不会重复计算业绩或奖金。

最后三项涉及定时任务、Redis故障和支付回调，不能只凭本脚本判定，需要结合数据库、Redis和操作日志完成验收。

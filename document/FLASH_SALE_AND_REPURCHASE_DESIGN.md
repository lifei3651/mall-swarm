# 秒杀与复购商城基座设计

## 1. 总体边界

- 普通商城、限时秒杀、会员复购是三种明确的整单业务类型：`NORMAL`、`FLASH_SALE`、`REPURCHASE`。
- 秒杀和复购默认关闭；未启用时前台不显示入口，接口也拒绝创建对应订单。
- 三种商品不能混合下单。秒杀与复购使用“立即购买”的独立结算清单，不写入普通购物车。
- 订单、财务、ERP、支付、物流和售后继续复用可靠的主链路；价格、PV、限购、奖金准入和库存资格在业务类型层隔离。

## 2. 秒杀链路

### 后台配置

位置：

- `商城设置 → 秒杀与复购模式`：总开关与奖金方式。
- `商品与库存 → 秒杀活动`：活动商品/SKU、秒杀价、秒杀PV、活动库存、每人限购、开始结束时间和状态。

### 高并发防护

1. 网关和应用限流先挡住短时间重复请求。
2. Redis Lua 在一次原子操作中检查会员是否重复、检查活动库存并扣减。抢完的请求不进入数据库订单事务。
3. 数据库以条件更新再次原子扣减活动库存，是Redis异常或数据漂移时的最终防超卖边界。
4. 订单事务仍原子扣减SKU和商品实物库存，防止活动库存正确但仓库库存已被其他渠道占用。
5. `(活动, 会员)` 唯一约束防止跨实例重复抢购；订单提交同时保留请求幂等保护。
6. Redis不可用时降级为本机限流加数据库原子扣减，服务可继续运行，但承载能力下降，应触发运维告警。

待付款订单取消或超时会回补实物库存、活动库存并释放该会员的本场资格；已支付订单退货时按实际退回数量回补库存，但不允许该会员借退款重复参加同一场活动。

## 3. 复购商城链路

### 后台配置

位置：

- `商城设置 → 秒杀与复购模式`：总开关、进入资格、奖金方式。
- `商品管理 → 编辑商品 → 销售渠道`：是否进入普通商城/复购商城、复购价、复购PV、复购累计限购；SKU可单独覆盖复购价和PV。

准入支持：

- 完成首笔有效支付的会员；
- 代理及以上；
- 全部正常注册会员。

复购商品可同时在普通商城销售，也可仅在复购商城销售。复购订单只使用复购价格、复购PV和复购限购，不读取普通商城限购累计数。

## 4. 奖金与客户定制

秒杀和复购分别支持：

- `NONE`：不进入业绩、关系快照、奖金和待结算余额链路（基座默认）。
- `STANDARD`：复用普通商城现有奖金规则。
- `CUSTOM`：预留客户专属模式。在客户规则尚未开发并验收前，系统明确禁止该类订单下单，避免用错误口径产生奖金。

客户交付时必须确认复购/秒杀是否与直推奖、团队奖、同级奖、复购奖等叠加，以及退款冲减口径。未确认前不自动组合奖励。

## 5. 发布与容量验收

本功能包含数据库迁移 `V202608121635__flash_sale_and_repurchase_foundation.sql`。正式启用秒杀前还应按客户预估峰值进行压测，至少验证：

- 同一会员重复请求只生成一张有效订单；
- 总成功数量不超过活动库存和实物库存；
- Redis故障降级时不超卖；
- 待付款超时、取消、退货后的库存和资格符合上述规则；
- 支付回调重复通知不重复计算奖金；
- 多实例环境下唯一约束、限流和原子扣减均生效。

基座发布后两个总开关仍保持关闭，不会自动向现有商城客户开放。

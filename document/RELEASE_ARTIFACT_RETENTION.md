# 发布候选产物留存规范

生效日期：2026-09-22

本文件是商城发布候选二进制产物的唯一留存规范。候选包留存与生产数据备份是两套账，任何一方都不能替代另一方。

## 1. 留存边界

1. 源码、构建脚本、逐文件哈希、迁移集合、准入结果和回执永久提交 Git；密码、令牌、私钥、真实客户数据和私有配置禁止进入 Git。
2. 完整二进制候选包不得放入普通 Git 对象。每个被冻结候选必须同时保留：
   - 本机工作副本；
   - 一份与当前主机、当前工作区相互独立的耐久副本，例如受控 GitHub Release asset 或开启版本锁定的私有对象存储。
3. 只有耐久副本上传完成，并从耐久存储回读后重新计算 SHA-256 与本机冻结值完全一致，才算“耐久冻结完成”。只保存源码和哈希，不等于保存了同一字节候选包。
4. 生产数据库、上传文件和运行配置的备份按生产备份规范保存；它们不代替候选包。候选包也不代替生产数据备份。

## 2. 必须记录的回执

每个候选的 QA 目录必须记录以下字段，且回执随 Git 永久保存：

- 版本、构建号、产品提交和源码树；
- 本机文件名、字节数和 SHA-256；
- 耐久存储提供方、对象标识或不可变地址；
- 上传时间、上传结果和保留期限；
- 回读时间、回读字节数和回读 SHA-256；
- 执行人、审批依据和是否含敏感文件的门禁结果；
- 作废时间、替代候选及删除审批（如适用）。

没有真实回执的字段必须写“未完成”，不得预填成功或根据源码推断成功。

## 3. 放行与保留期限

1. 耐久冻结未完成时，禁止清理本机候选，禁止进入服务器部署（S）和微信开发版上传（W）。
2. 未发布候选在被明确作废、且替代候选已经完成 C/T 后，仍至少保留 30 天。
3. 任何实际部署到服务器或上传到微信平台的候选至少保留 365 天，并始终覆盖当前线上版本及其前两个版本。
4. 保留期内不得用“相同源码重新构建”的文件替换原候选；如原候选丢失，必须将其标记为不可恢复并重新分配版本、重新完成 C/T。

## 4. 校验清单作用域

不同根目录的文件必须使用不同清单，禁止把仓库路径、候选包内部路径和平台上传目录混在同一 `sha256` 文件中：

- `REPOSITORY_ARTIFACTS.sha256`：从仓库根目录校验本机候选及其本地导出元数据；
- `CANDIDATE_INNER.sha256`：解压统一候选包后，从包根目录校验内部产物；
- `MIGRATIONS.sha256`：从仓库根目录校验迁移集合；
- `EVIDENCE.sha256`：从候选 QA 目录校验证据文件本身。

每份候选说明必须给出可直接执行的校验命令和明确的工作目录。

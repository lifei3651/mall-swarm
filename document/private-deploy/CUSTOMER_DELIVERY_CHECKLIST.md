# 客户独立部署交付清单

这份清单用于每个客户单独部署商城基座时的交接。原则是：客户资料、域名和密钥可替换；商城代码、数据库结构和业务规则不因换客户而被临时改写。

开始人工验收前，先进入后台“商城设置 → 商城资料与客服”查看“客户交付预检”。预检用于发现缺失配置和明显测试内容，不能替代下方真实资金、物流、短信和备份恢复实测。

## 0. 客户项目身份

- [ ] 使用`document/customer-project/scripts/derive-customer-project.sh`从已验收基座提交派生，没有手工复制商城工作区
- [ ] `CUSTOMER_PROJECT_ORIGIN.json`中的客户标识、基座版本和完整提交哈希已核对
- [ ] 客户项目是独立Git仓库，初始没有远程；人工核对后只连接该客户自己的私有远程仓库
- [ ] 项目内没有基座`.deploy`、正式服务器目标、历史远程发布脚本、`.env`、证书或私钥
- [ ] Android接口、支付宝回调和Nginx域名占位值已按该客户资料替换，且没有指向商城基座正式域名
- [ ] 客户专属奖金制度、资料、密钥和UI改动只存在于客户项目，不反向合并到商城基座
- [ ] 若同步过基座公共修复，已先运行`upgrade-customer-project.sh`只读预检，冲突经人工处理，应用后重新完成全量测试

## 1. 客户资料（只改配置）

- [ ] 公司全称、统一社会信用代码、营业执照、备案信息
- [ ] 客服电话、客服邮箱、售后地址和工作时间
- [ ] 商城名称、Logo、ICP备案号、版权信息
- [ ] 首页主题、Banner、模块显隐、分类显隐和底部导航文案
- [ ] 用户协议、隐私政策、交易与售后规则中的公司占位符已替换

资料只通过后台“商城资料与客服 / 商城视觉与页面 / 协议与规则”或该客户的环境配置文件维护，不直接改组件源码。

## 2. 支付与短信

- [ ] 客户小程序已认证、已开通小程序支付权限，AppID与客户微信支付商户号完成绑定
- [ ] 微信公众平台“订单管理”已签署订单中心授权协议并开启“订单信息录入”，订单详情路径严格配置为`pages/order-detail/index?orderNo=${商品订单号}`
- [ ] 从微信“我 → 小店与卡包 → 小程序购物订单”抽测单商户及联合支付订单，均只能在登录后打开本人对应订单，不能查看其他会员订单
- [ ] 已根据实际服务类目核对《实物交易类小程序跳转规范》；不使用受限营销跳转时记录限制即可，确需恢复时使用真实品牌/业务材料申请，不把零售商城误报为B2B
- [ ] 微信支付商户号、商户证书序列号、API v3密钥、微信支付公钥ID及两份PEM文件来自同一客户商户
- [ ] 微信支付异步通知为`https://客户域名/api/pay/wechat/notify`，退款通知为`https://客户域名/api/pay/wechat/refund-notify`
- [ ] 微信开发者工具和真实手机完成小额支付、用户取消、余额不足/密码错误、重复通知、主动查单、超时关单、关单与支付竞态迟到退款及售后原路退款验收
- [ ] 微信支付分账如为客户合同范围，已单独确认接收方、比例、冻结期、退分账和合规方案；不得以普通支付/退款已接入代替分账验收
- [ ] 支付宝企业主体、APPID、PID（作为 `ALIPAY_SELLER_ID`）、应用私钥和支付宝公钥已核对为同一应用
- [ ] 手机网站支付已开通，接口使用 `alipay.trade.wap.pay`，`product_code=QUICK_WAP_WAY`
- [ ] 异步通知地址为 `https://客户域名/api/pay/alipay/notify`
- [ ] 同步回跳地址为 `https://客户域名/api/pay/alipay/return`
- [ ] 真实小额支付、异步通知、重复通知和订单查询兜底均已验收
- [ ] 短信签名、模板编号、AccessKey 通过服务器受保护环境变量注入，未进入前端或 Git

更换支付或短信资料时，只替换该客户的受保护环境变量并重启服务，不修改支付控制器、回调验签和订单状态代码。

## 3. 独立运行环境

- [ ] 一客户一服务器、一数据库、一套环境变量
- [ ] 全程使用 `document/private-deploy/scripts/deploy.sh`，没有直接执行 `docker compose up`
- [ ] `.env` 由 `prepare` 自动生成且权限为 `600`，不存在 `change_me`、固定验证码或模拟支付
- [ ] 云安全组只公开80/443，SSH仅固定IP/VPN；已用 `firewall` 登记证据编号
- [ ] `check` 强制预检通过，Compose只有Nginx、商城后端、MySQL和Redis四个必要服务
- [ ] 首次安装已执行 `deploy.sh bootstrap-admin`，没有使用源码内置账号，首个管理员登录后已完成强制改密
- [ ] `verify` 显示数据库基础表存在、成功迁移数与当前迁移目录一致、失败迁移为 0
- [ ] MySQL、Redis和后端均没有宿主机端口；数据库维护只通过SSH登录服务器后执行容器命令
- [ ] HTTPS响应包含 CSP、Permissions-Policy、HSTS 等安全头，常见扫描路径返回404
- [ ] `SERVER_ADDRESS`、HTTPS、反向代理和健康检查已配置
- [ ] `/opt/lingqimall/uploads` 已做持久化挂载
- [ ] 生产配置文件权限符合最小权限要求，密钥文件不进入提交
- [ ] `DATA_ENCRYPTION_KEY` 已纳入客户受控密钥备份，恢复演练确认数据库与原加密密钥配套使用
- [ ] `DATA_ENCRYPTION_WRITE_ENABLED=true`，既有系统已按“两阶段发布”验证后再执行历史数据加密
- [ ] 云磁盘、数据库快照和异地备份已启用客户云平台的静态加密，解密权限只授予备份恢复人员
- [ ] 首次上线前完成全量备份，记录备份路径和版本号
- [ ] 上线后核验商城、管理后台、后端健康、Nginx、MySQL、Redis
- [ ] `verify` 部署后验收通过，并保存 `reports/security-postflight-*.txt`
- [ ] 公开商城、团队 H5、管理后台三份线上 `version.json` 的版本、Git 提交和构建批次与本次交付记录一致

## 4. 业务验收边界

- [ ] 首次安装后只有一个启用中的奖金程序；未完成客户制度时必须为 `CUSTOMER_BONUS_DISABLED`
- [ ] 默认关闭程序下，注册、邀请绑定、下单、支付、履约和售后可正常运行，订单不产生奖金
- [ ] 基座演示分类、轮播、公告、商品和规格均处于后台草稿状态，客户正式资料未准备好时不得公开
- [ ] PV、团队业绩、奖金来源和奖金流水默认不公开，只有客户制度和端权限验收通过后才按客户项目开放
- [ ] 商品、分类、规格、评价、订单、带图片凭证的售后和 ERP 对接各抽测一条完整流程
- [ ] 收货地址、订单备注、购物车删除/结算二次提示、支付密码和余额流水已抽测
- [ ] 退款申请、取消退款、退款状态展示和资金流水已抽测
- [ ] 操作日志能看到被调整会员、操作管理员、前后值和原因
- [ ] 备份恢复演练已记录结果

## 5. 客户规则确认（不预设奖金模型）

- [ ] 冻结/释放时点、冷却期、退款冲正和提现后追回已由客户确认
- [ ] 部分退款、组合商品、运费/优惠分摊和异常订单口径已由客户确认
- [ ] 风控上限、利润率下限、亏损订单处理和人工复核流程已由客户确认
- [ ] 确认使用哪套奖金模型、会员模型和 PV 规则后，再建立客户专属规则包
- [ ] 客户专属规则发布时替换默认关闭程序，确认数据库仍然只有一个启用中的奖金程序

奖金、会员、PV 不在基座交付中写死。客户确认模型后，应以独立规则包实施、测试和发布，避免改动通用商城流程。

## 6. 发布留痕

- [ ] 保存`CUSTOMER_PROJECT_ORIGIN.json`，记录本次客户版本对应的基座来源提交
- [ ] 保存最近一次`CUSTOMER_PROJECT_UPGRADE_REPORT.md`，确认客户项目记录的基座提交与本次交付一致
- [ ] 记录版本号、提交哈希、发布人、发布时间和备份路径
- [ ] 记录本次是否执行数据库迁移；未授权不得删除或清理业务数据
- [ ] 发布后保存健康检查和关键页面验收结果
- [ ] 线上出现问题先保留日志和备份，再定位对应版本，不直接覆盖另一台电脑的改动

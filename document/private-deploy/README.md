# 客户私有化安全部署包

本目录是未来客户部署的唯一入口。部署人员不需要记住端口、密钥和检查命令，但必须使用
`scripts/deploy.sh`；禁止绕过该入口直接执行 `docker compose up`。

当前商城基座只部署四个必要服务：Nginx、商城后端、MySQL、Redis。旧模板引用的网关、搜索、
监控、MongoDB、RabbitMQ、Elasticsearch和Nacos不是当前仓库的可运行组件，已全部移除，避免
交付时开放无用服务或引用不存在的 Dockerfile。

## 安全边界已经写死

- 公网只发布 Nginx `80/443`。
- MySQL、Redis和后端均不映射宿主机端口，只能在 Docker 内部网络访问。
- 数据网络设置为 Docker `internal`，Nginx不能直接读取数据库和Redis。
- 后端强制 `prod`，强制关闭模拟支付、固定验证码和Nacos客户端。
- 后端使用非 root 用户、`no-new-privileges`和只读根文件系统运行；只有上传卷和临时目录可写。
- `.env` 必须为 `600`，支付、短信、数据库、会话和敏感字段加密密钥只进入确实需要它们的容器。
- 公开商城、团队H5、一体化H5和后台使用四个独立静态目录；默认拆分部署下，公开域名无法通过猜路径读取团队H5或一体化构建。
- 生产静态资源禁止 source map，公开商城、团队H5、一体化H5与后台构建版本必须等于仓库根 `VERSION`。
- 数据库升级前自动备份；迁移按版本号、SHA-256和当前部署机的单机锁登记，重复或冲突立即停止。
- 首次安装先导入无测试账号的分销基础库及 ERP/经营地址前置结构；只登记基础库确实已吸收且不可重复执行的迁移，其余迁移仍逐项真实执行。已有客户没有首次安装标记，不会误走新装路径。
- 首次安装会把基座演示分类、轮播、公告、商品和规格转为后台草稿，并建立唯一启用的 `CUSTOMER_BONUS_DISABLED`。因此新客户可先验收普通交易与售后，但不会误公开测试内容或产生未确认奖金；已有任一奖金版本的客户不会被重复初始化覆盖。
- MySQL、Redis和Nginx使用经过测试的明确版本标签；升级镜像版本必须先在隔离环境重跑全部流程，不能临时改成 `latest`。
- 云安全组必须登记证据，SSH禁止 `0.0.0.0/0` 或 `::/0`，但最终仍需在客户云控制台真实执行。
- 客户云磁盘、数据库快照和异地备份必须启用云平台静态加密，并以独立 IAM/KMS 权限控制解密；仓库不会保存客户主密钥。

## 标准部署流程

### 1. 生成生产构建

```bash
cd document/private-deploy
./scripts/deploy.sh build
```

该命令执行后端完整测试与打包、商城三种模式测试与构建、后台测试与构建，再分别放入忽略 Git 的
`html/public`、`html/team`、`html/integrated`、`html/admin`。默认部署继续使用拆分的公开商城与团队 H5；客户确认采用一体化模式时，将一体化目录配置为该客户 H5 域名的静态根目录，并把该域名受控 Nginx 配置中的 `$shop_surface` 固定为 `integrated`。公开和团队域名分别固定为 `public`、`team`，不得透传浏览器自带的版本请求头。发现测试失败、公开包含团队业务文字或接口、一体化功能分块缺失、source map 或版本不一致会停止。

### 2. 为客户生成独立密钥

```bash
./scripts/deploy.sh prepare \
  --domain mall.customer.com \
  --team-domain team.customer.com \
  --admin-domain mall.customer.com \
  --ssh-cidr 203.0.113.10/32 \
  --project customer_code \
  --customer-name 客户公司名称 \
  --brand 客户商城名称
```

公开商城域名用于 App/小程序及普通购物，团队H5必须使用另一个域名。程序使用 OpenSSL 生成独立的 MySQL、Redis、会话和数据库敏感字段加密密钥，并创建权限为 `600` 的 `.env`。
如果 `.env` 已存在会拒绝覆盖，防止客户密钥丢失。

`DATA_ENCRYPTION_KEY` 用于解密身份证、银行卡和 ERP 凭证。它必须和数据库备份一起进入受控密钥备份；丢失后对应密文无法恢复，禁止在已有客户数据时重新生成或替换。

客户新部署固定使用 `DATA_ENCRYPTION_WRITE_ENABLED=true`。已有线上环境升级时采用两阶段方式：先用新程序和原密钥、`false` 启动完成健康检查；确认新程序可用后改为 `true` 再启动并迁移。迁移后如需回退，必须回退到同样支持解密的新程序，不得直接换回不识别密文的旧版本。

### 3. 配置证书、支付、短信和实名认证

- 将同时覆盖公开商城、团队H5和后台域名的证书保存为 `certs/cert.pem`，私钥保存为 `certs/key.pem`并设为 `600`。
- 客户未开通支付宝或短信时保持对应 `ENABLED=false`、资料留空。
- 启用支付宝时必须填写同一应用的APPID、应用私钥、支付宝公钥和客户HTTPS回调地址。
- 启用微信支付前必须确认客户小程序已认证、已开通小程序支付权限，且AppID已绑定客户商户号。商户API私钥与微信支付公钥分别放入`secrets/wechat-pay/apiclient_key.pem`和`secrets/wechat-pay/wechatpay_public_key.pem`，私钥权限设为`600`；再填写商户号、证书序列号、公钥ID、32字节API v3密钥及支付/退款HTTPS回调。程序已覆盖预下单、调起支付、查单、验签通知、关单和退款，但真实资料齐全并完成真机资金验收前必须保持`WECHAT_PAY_ENABLED=false`；微信支付分账需按客户合同另行设计和验收。
- 启用短信时必须填写客户自己的AccessKey、签名及全部已审核模板编号。
- 实名认证默认关闭。启用前必须开通客户自己的腾讯云实名认证服务，填写该客户的 SecretId/SecretKey，并确认敏感个人信息单独同意、隐私政策和服务商披露；姓名和身份证号只进入后端加密存储与官方核验接口，不进入前端构建、普通日志或导出。
- 同一身份证允许认证客户合法持有的多个商城账号，每个账号只能绑定一份实名信息；未满18周岁不能使用余额互转和提现。公开商城与团队拆分版不开放余额互转，只有服务器签发为 `integrated` 的三合一会话才能调用互转接口。
- 验证码短信使用 `SMS_*`；服务通知短信使用完全独立的 `EXTERNAL_NOTIFICATION_*` 和 `NOTIFICATION_SMS_*`。两套模板不得互相回退或复用。
- 服务通知默认关闭。后续启用前必须同时完成：客户凭据和签名、六类低频服务通知审核模板、供应商价格、租户/事件/渠道三层日月费用上限、用户授权与合格终端摘要、回执验签及隐私验收。直接改数据库事件开关不能替代这些条件。
- App 推送和小程序订阅通知当前只有测试模拟适配器，生产三项 `NOTIFICATION_MOCK_*` 必须保持 `false`；它们与已经接入的微信小程序支付是两套独立能力。
- 真实密钥不进入Git、镜像、前端、聊天截图或工单正文。

### 4. 在云控制台设置安全组并登记证据

云安全组属于客户云账号，仓库无法替客户点击控制台。必须在控制台只公开：

- `80/tcp`、`443/tcp`：公网。
- `22/tcp`：仅固定运维IP或VPN网段；数据库维护通过SSH进入服务器后使用容器命令，不开放3306。
- 禁止公网开放 `3306`、`6379`、`8086`及所有临时调试端口。

完成后登记截图文件名或工单编号：

```bash
./scripts/deploy.sh firewall \
  --ssh-cidr 203.0.113.10/32 \
  --evidence cloud-sg-ticket-20260813
```

### 5. 强制预检

```bash
./scripts/deploy.sh check
```

该步骤会展开最终 Compose 配置并检查端口、内部网络、特权模式、Docker socket、密钥容器边界、
生产模式、测试开关、域名、CORS、云安全组确认、TLS有效期、构建产物和文件权限。任何一项失败都
不会继续。

### 6. 部署或升级

```bash
./scripts/deploy.sh apply
```

已有数据库时先生成并校验升级前全库备份；发现历史数据卷但数据库无法启动时直接停止。随后确保
MySQL和Redis健康，执行版本化迁移，只重建商城后端和Nginx，不重启数据库与Redis。Nginx会强制重建
以重新绑定原子替换后的静态目录，避免升级后仍读取旧文件。部署完成后自动执行安全验收。

### 7. 创建首个管理员

首次安装且数据库中没有管理员时，先显式创建客户自己的首个管理员：

```bash
./scripts/deploy.sh bootstrap-admin
```

该命令只允许在管理员表为空时执行，密码不会写入文件或命令行；首次登录后必须立即改密。

### 8. 独立复验

```bash
./scripts/deploy.sh verify
```

复验内容包括所有必要容器、真实监听端口、数据库与Redis未映射公网、数据库基础表和完整迁移总账、
唯一启用的客户奖金程序、内部后端健康、公开商城/团队H5/后台的版本与Git构建身份、HTTPS证书、安全响应头，以及公网 Actuator、
Swagger和接口文档返回404。结果保存到权限为 `600` 的 `reports/`，记录版本、Git提交、云安全组证据和
安全边界，不记录任何密码或私钥。

## 日常备份与恢复

升级前备份由统一部署入口自动完成。日常备份仍可执行：

```bash
./scripts/backup.sh
```

恢复属于破坏性操作，必须先停止业务、保留当前备份并明确目标文件：

```bash
./scripts/restore.sh --confirm ./backups/mysql/指定备份.sql.gz
```

## 仍需按客户确认的业务

品牌资料、经营资质、物流服务商、ERP、售后期限、支付商户、短信、秒杀、复购和奖金制度必须按
客户确认配置或定制。部署安全流程不会替客户决定业务制度，也不会自动执行真实支付、退款或短信。

## 结论与影响范围

不需要全部推倒重新设计，但必须把小程序当作独立客户端，重新验收启用的完整业务路径。此前 H5 通过不代表小程序通过，不能只对齐颜色和页面标题。

- H5 是 `mall-shop-web` 的 Vue 页面，小程序是 `mall-mini-program` 的原生页面；修一端不会自动修另一端。
- H5 默认请求 `/api`；小程序请求 `https://lingqimall.com/api`。商品、分类、价格、库存、运费、普通订单、限购、地址及售后最终使用同一商城后端。不是两套订单库或奖金引擎。
- 登录有微信专用适配；H5 使用网页会话，小程序使用微信登录及商城令牌；支付调起方式与可用渠道也不同。这是需要单独验证的端适配，不等于另起一套交易规则。
- 两端购物车目前均为各自设备本地保存，不是服务端同步购物车。本批补小程序按账号隔离，不代表 H5 和微信购物车会互相同步。订单、会员等已保存的服务端资料仍由共同后端提供。
- 本批不修改 H5、管理后台、后端业务代码或线上配置；没有上传、提审、部署、真实授权、短信、支付或退款。

## 本批限购规则与修复

1. 同一会员、同一商品跨规格合并；不是“每点击一次重新获得限购额度”。
2. 加购之前先取新商品详情，核对上架状态、所选规格、库存与价格；普通加购按现购物车该商品总件数＋本次件数检查。
3. 随后调用与 H5 相同的会员限购接口，历史购买量由服务端计算。待付款也占额度；关闭等状态的释放依照后端实际订单状态，不能由客户端自行扣减，也不承诺任意部分退款马上释放。
4. 首页、分类、详情、购物车加号共享 `utils/purchase-limit.js`；首页和分类另共用快捷加购与规格弹层，减少后续只修一处的风险。
5. 结算只合并已选商品；直接购买只计算本次数量。拒绝或校验失败不悄悄加购、不跳过校验，结果使用中央确认弹窗。
6. 重复加同一规格时刷新单价/名称，保留原勾选状态；重复点击、离开页面、换会话的晚响应不能写入新购物车。
7. 小程序改为按商城会员 ID 存储购物车；退出后不展示，重新登录恢复本人条目。旧 `mall_mini_cart` 缓存没有可信归属，保留原数据但不认领给任何账号，首次进入购物车明确提示重新添加。已有服务端订单不变。
8. 有规格的商品在小程序保留明确选规格，与 H5 当前自动选第一个有库存规格的快捷行为有意不同；不在用户未选时买入另一规格。

# 商城前台共用设计系统

生效日期：2026-09-20。适用于微信小程序、公开商城 H5、团队商城 H5 和同源码一体化 H5。

## 设计方向

以“商城说明”已确认的效果为基线：整齐、简洁、信息优先。页面采用浅灰背景、白色内容组、轻边框、低阴影；减少同级大卡片和装饰性标题，不用更多色块制造层级。

## 唯一控制入口

| 内容 | 小程序 | H5 |
| --- | --- | --- |
| 主题变量、按钮、价格、卡片、状态、客服入口 | `mall-mini-program/app.wxss` | `mall-shop-web/src/assets/styles.css` |
| 页面样式 | 只负责排列、宽度、留白和响应式 | 只负责排列、宽度、留白和响应式 |
| 自动门禁 | `scripts/check-storefront-ui-contract.mjs` | `scripts/check-storefront-ui-contract.mjs` |

页面不得重新定义共用组件的品牌色、价格色、底色、圆角、边框或阴影。确需新增视觉变体时，先在共用层增加有业务含义的变体，再由页面引用。

## 共用组件

- `ui-card`：白色内容组。相邻信息优先放进同一卡片，用分隔线分组，不为每一行创建独立卡片。
- `primary-button` / `btn primary`：当前操作区唯一主操作，品牌色实底。
- `secondary-button` / `btn secondary`：查看、返回、取消等普通次操作，浅灰底。
- `danger-button` / `btn danger`：删除、退出、不可恢复的关闭操作，红色语义。
- `ui-utility-button`：复制、查询、刷新等行内辅助操作；不得套用整行主按钮尺寸。小程序使用 `size="mini"`，较长文案再增加 `ui-utility-button--wide`。
- `ui-price`：所有成交价、实付款、合计金额。只读取价格色变量，不允许页面写死颜色。
- `ui-status-pill`：订单、售后等业务状态。普通状态读取品牌浅色，警告和危险状态必须使用语义变体。
- `ui-list-row`：设置、帮助、说明、折叠信息的统一行。
- `ui-service-entry`：联系客服、客服工单、联系方式的统一入口；宫格中使用 `ui-service-entry--tile`，紧凑弹层中使用 `ui-service-entry--compact`。
- `ui-action-bar`：右对齐操作组；同一组最多一个主按钮。

## 页面骨架

### 首页、分类、购物车

商品图、两行内标题、辅助说明、销量、`ui-price` 和数量控件保持同一顺序。首页和分类的加购状态要与购物车同步，不再为三个页面分别设计数量控件。

### 订单列表

顺序固定为：订单号与状态、商品、履约/售后摘要、件数与实付、操作组。查看详情和售后为次操作；支付、确认收货、去评价按当前任务选择一个主操作。

### 订单详情

顺序固定为：紧凑订单号、物流与隐私地址、商家与商品、金额、折叠订单信息、售后进度、底部操作。物流和地址属于同一履约内容组；地址默认折叠，不展示姓名和手机号。

### 客服与帮助

任何“联系客服”“客服工单”“查看联系方式”都必须使用 `ui-service-entry`。不得再出现一处文字链接、一处实心按钮、一处自定义卡片的三套外观。

## 变更流程

1. 先判断是否已有共用组件；有则只引用，不复制样式。
2. 修改共用组件时同时核对小程序和 H5 的同名组件。
3. 执行 `scripts/check-storefront-ui-contract.mjs`；门禁失败不得构建或发布。
4. 至少验收 320px 和 390px 两个移动宽度，并记录加载、空态、错误、禁用、长内容和弹层状态。
5. 发布前运行小程序检查、两端测试和 H5 三种构建；本地通过不等于已发布。

## 禁止事项

- 不在页面文件中给共用组件加 `!important`。
- 不为同一个业务动作重新发明按钮颜色或圆角。
- 不用硬编码颜色覆盖后台配置的按钮色和价格色。
- 不只修改截图中的一个入口；必须同步同业务、同端和另一端。
- 不以“先发布再看”为验收方式。

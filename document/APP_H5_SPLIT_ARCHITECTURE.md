## 构建方式

商城前端从同一套受控源码产生三个可选静态包：

```bash
cd mall-shop-web
npm run build:public
npm run build:team
npm run build:integrated
```

- `dist/`：公开商城包，构建结束自动扫描团队文字、路由和接口；发现邀请、团队、奖金、提现、复购等内容会直接构建失败。
- `dist-team/`：团队 H5 包，只包含团队业务页面。
- `dist-integrated/`：一体化 H5 包，在同一入口中同时包含普通商城和团队业务；构建后自动核对商城、订单、复购、邀请、业绩、钱包和转账页面是否齐全。
- Android Capacitor 始终使用公开商城 `dist/`，不会打入团队 H5。
- 微信小程序不是网页构建产物，客户确定上架需求后必须新增独立小程序前端，复用 `/shop/public/**` 及普通商城接口。

## 账号和奖金边界

两端共用同一商城账号体系，邀请关系和推广资格分开处理：

1. 公开商城普通注册不绑定邀请人并写入 `team_opt_in=0`；从受邀链接或二维码进入时，注册提交本身直接完成一次性关系绑定，不要求用户再确认，也不展示奖金宣传。
2. 已有普通账号进入团队 H5 后可以首次填写邀请码。关系确认使用会员行锁和数据库条件更新，绑定后本人不能重复修改。
3. `team_opt_in`只表示用户主动进入团队业务，不能单独证明推广资格。推广资格按客户级模式执行：新客户默认关闭；可选受邀即开通、后台审核；首笔有效订单开通只作为老商城兼容方式。
4. 只有已经开通有效推广资格的账号，其符合客户奖金程序的订单才冻结团队关系并进入业绩和奖金链路。普通公开购物不会自动获得资格。
5. 客户奖金名称、级别、比例、复购条件和计算公式不写入基座模式；每个客户仍在独立项目实现并单独验收。
6. 原一体化商城的历史会员和当前线上客户保留既有资格方式，不删除、不重算历史关系、业绩或奖金。

## 部署边界

客户部署必须提供两个不同域名，例如：

- 公开商城：`mall.customer.com`
- 团队 H5：`team.customer.com`

部署包将静态文件分别放在 `html/public`、`html/team`、`html/integrated`、`html/admin`。默认拆分模式由 Nginx 对不同域名使用不同静态根目录，因此公开域名无法通过猜测 `/team` 路径下载团队构建；一体化目录只在客户明确选择一体化 H5 时作为该客户 H5 域名根目录。证书必须覆盖实际启用的商城、团队 H5 和后台域名，CORS 必须明确列出这些 HTTPS 来源。

当前测试服务器使用：

- 公开商城：`https://lingqimall.com`
- 团队 H5：`https://www.lingqimall.com`
- 商家后台登录：`https://lingqimall.com/merchant/login`
- 平台总后台登录：`https://lingqimall.com/platform/login`

一体化模式是可选交付方式，不与拆分模式同时作为同一客户的主入口。客户不需要 App / 小程序上架隔离时，可将 `dist-integrated/` 作为客户 H5 域名的静态根目录；需要 App / 小程序合规边界时，继续部署 `dist/` 与 `dist-team/` 两个独立域名。两种方式共用同一后端、数据库和管理后台，不复制业务代码或数据。

## 可选多商户模块

- 多商户直接叠加在这套拆分核心上，不再复制第三套项目；不启用时，现有商品和订单继续按平台自营运行。
- 商品可绑定一个商户；购物车允许平台自营和多个商户商品一次支付，系统内部生成一张支付父交易和每销售方一张履约子订单，运费、发货、售后、退款、发票与货款仍按子订单隔离。
- 商户货款按下单时保存的成本单价乘有效数量计算。例如成本价 50 元、有效销售 10 件，应结货款为 500 元；平台不另收服务费。
- 支付后先进入“待结算”，订单确认收货、客户配置的售后期限结束且没有进行中售后后转为“可提现”。退款按原成本快照冲回；已提现后发生退款时形成商户欠款，后续货款优先抵扣。
- 财务流程为“申请提现 → 冻结余额 → 登记发票/调整 → 确认实际打款或驳回”。系统不设置“扣税”字段，只保存通用调整金额与原因，避免系统替财务作税务判断。
- 商品销售区分为普通商城、复购区、报单区三个独立开关；团队奖金模式分为继承原规则、不发团队奖、标准团队奖、客户定制。标准团队奖商品只允许进入复购区或报单区，客户定制规则未实现前拒绝下单。
- 当前基座已在同一管理后台提供受限商户工作台：商户账号只能维护本商户商品、商户私有服务地址，查看本商户货款并申请提现；不能进入平台看板、会员、奖金、商品审核、保证金入账或打款页面。履约状态允许时商户可处理本商户历史订单的单笔/批量发货和正常售后，平台接管或冻结履约后页面和后端同时关闭这些操作。

详细规则见 [《多商户业务设计》](./MULTI_MERCHANT_DESIGN.md)。

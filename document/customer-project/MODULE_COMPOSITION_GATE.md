# 客户项目模块选择与放行门禁

> 2026-09-26 初版，2026-10-01 校对至固定基座 1.0.174 / `72f4db84`，45条迁移已部署；[同版分发回执](../qa/2026-10-01-release-snapshot-174/README.md)。适用于从通用商城基座派生的独立客户项目；当前基座测试站不是任何客户的正式商城。本文是选型与验收合同，**不是已实现任意模块即插即用的证明**。早期边界审查保留在 `../qa/2026-09-26-base-module-boundary-audit/README.md`，不能把其中“线上167/未部署”当成当前状态；全局优先级见 `../MALL_CLOSURE_LEDGER.md`。

## 每个客户先冻结选择，不按页面开关猜模块

当前固定174原JAR已经完成[61组新空库HTTP实跑](../qa/2026-10-01-runtime-174/README.md)：默认关闭、角色API/跨商户、邀请两态、持续消费直推、余额部分退款、普通退货、实际结算/追回及财务统计。客户可复用此证据作为基座来源；仍须验其所选配置、界面和外部凭据。它不是任意模块组合或客户现场已验的承诺，不据报告中的限制扩建本轮基座。

客户项目在开发前记录：来源基座提交、公开商城/小程序/团队 H5 的选择、支付渠道、余额、奖金/团队、营销、商户模式、物流、客服/短信和外部 ERP；每项填 `启用`、`不启用` 或 `待客户确认`，并写明负责人、依赖与验收用例。没有可核对的选择记录，不得生成“已按需组装”的交付结论。

| 能力 | 当前边界 | 客户项目选择规则 |
|---|---|---|
| 账号与权限、商品库存、购物车、订单、支付/退款安全抽象、履约售后、审计 | 交易内核 | 不按运营模块裁剪；所有客户项目均验状态机与账务守恒 |
| 微信/支付宝支付渠道 | 已有独立配置和接口；客户交付预检允许至少一条配置完整。服务端新单通道门禁已纳入174，阻止未配置渠道产生不可支付的待付款单，历史已建订单的回调/退款保留。已有自动测试及历史隔离HTTP拒绝证据；**配置完整不代表真实联通** | 选择实际渠道；未选渠道必须保持关闭且不能被直达接口用于新单，旧订单仍须安全结清。所选渠道须用客户凭据完成支付、回调、退款和对账；基座关闭态证据不代替客户渠道开通 |
| 余额 | 租户级“停止新余额交易”开关及顾客/后台入口、服务端新余额支付、转账和人工调账门禁已纳入174；旧账、退款、奖金和提现清偿保留。历史隔离HTTP已验余额支付→关模块→旧单退款及财务守恒，见[运行记录](../qa/2026-09-27-runtime-base-closure/README.md) | 不能只隐藏按钮就宣称移除；在客户所选版本/配置验开启/关闭、直达 API、旧单退款、存量资产清偿、奖金和资金守恒。首次密码的新旧订单页与真实短信仍按同版真机验收记录，不将历史隔离API通过扩大为所有手机路径通过 |
| 团队 H5、推广与奖金 | 客户派生默认奖金程序为 `CUSTOMER_BONUS_DISABLED`；基座174可选独立基础直接推荐佣金，复杂团队制度由客户项目实现；`--without-team-h5`公开商城＋后台全新空卷安装、同模式升级及HTTPS容器运行有历史实际证据，非仅构建预检 | 不选团队 H5 时使用配对的 `--without-team-h5` 并在客户隔离环境验资源/域名/回滚；不选奖金时验零奖金与权限边界。选基础直推须冻结比例、首笔/持续消费、参与商品、结算等待期并验普通B贡献A、不越级和部分/全额退款；站点不交付**不等于**奖金后端模块移除。历史单模式安装不代验客户云现场或拆分/一体化切换回滚 |
| 秒杀、复购区 | 有租户开关和顾客交易门禁；新下单与后台关闭共用行锁、秒杀锁序已补本地 C/T，历史订单支付/退款回补不受开关阻断 | 仅视为部分关闭能力；还须验隔离 MySQL 两事务并发、菜单、直达 API、任务、历史订单与奖金/退款组合，见 `../qa/2026-09-26-module-combination-continuation/README.md` |
| 优惠券 | 租户总开关和小程序/H5/后台、服务端新领券/新用券关闭态已纳入174；复购关闭时专用券停止新发行/领取/预占。对应迁移已部署，不再是仅结构副本；历史隔离HTTP已有关闭态拒绝证据，旧券退款与客户具体组合须各留运行证据 | 客户不选时在其隔离环境验证关闭态、旧券追溯和退款逆流程；基座平台发券、适用归属/商品范围与优惠成本承担分开配置，每单最多一券且不叠加秒杀。不开拓商家自主发券或跨店通用券 |
| 多商户 | 租户级“仅平台自营”开关已纳入174：阻断新商户入驻/启用、商户商品重新上架和新商户商品交易；关闭后商户商品不在公开目录/秒杀入口展示。历史订单支付、退款、结算及审计不按新销售开关截断。迁移已部署，历史隔离HTTP已有跨商户与关闭态证据 | 隐藏菜单或只运营一家商户不等于关闭；在客户隔离环境实测商品目录、直达 API、结算、旧单支付/退款及开关并发。标准新装与客户创建服务明确把新客户设为仅自营；历史迁移默认值 `1` 是为保持旧客户开启状态，**不得绕过创建服务直接插入新客户而省略该字段**。既有测试不是任意商户/模块组合交付承诺 |
| ERP | 已配置启停；本轮补上旧任务执行前门禁和自动队列过滤 | 未选或停用时不得继续外推订单/接受回传；选用具体厂商须单独完成授权、字段、签名与回传联调 |
| 微信物流、短信、实名、自动打款等外部服务 | 各自存在配置或代码边界，部分依赖平台开通与供应商凭据 | 逐项取得提供方实际回执；模拟状态机、配置保存或页面存在都不等于已开通 |
| 首页运营块、主题、版型、底部导航 | 装修层开关与排版配置 | 可以作为展示选择，但隐藏入口不等于关闭交易接口或后台任务 |

## 逐模块放行记录

每个选中/未选中模块都要在客户项目留一行以下记录，并保存证据链接：

`模块｜选择｜默认值｜页面/权限｜API/服务端门禁｜任务/回调｜数据与迁移｜对支付/退款/订单的依赖｜自动测试｜运行验收｜第三方回执｜结论`。

- **启用态**：从页面到 API、任务与账务走完整路径；权限角色和异常/重试/幂等均覆盖。
- **关闭态**：按钮与直达地址不可误用；API 明确拒绝或安全降级；已有待处理任务不得继续向外发消息/款项/订单；保留历史记录、退款和追溯能力，不清库。
- **组合态**：至少覆盖所选支付渠道 × 订单/退款、奖金关闭 × 订单/退款、营销关闭 × 普通下单、ERP关闭 × 旧待推任务；具体客户组合另补矩阵。
- **证据层级**：代码/自动测试、服务器部署、微信平台、真机运行、第三方回执分别记录。任一缺失不得用“模块已交付”笼统代替。

当前阻断项以总账 P0/P1 为准；本文件不授权自动发布、写客户生产库或接入真实资金。

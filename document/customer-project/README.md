# 客户独立项目派生工具

这套工具把“复制一份商城文件夹再修改”改为可追溯的客户项目创建流程。它只读取一个明确的商城基座 Git 提交，不读取未提交内容，也不会连接服务器、创建客户密钥、配置远程仓库或发布系统。

## 为什么不能直接复制文件夹

普通复制会同时带走基座 Git 身份、正式服务器脚本、历史发布包、验收截图、缓存和可能存在的本地配置；后续也无法准确回答客户项目从哪个基座版本开始。派生工具会移除这些基座专属内容，并为客户项目生成独立来源记录和独立 Git 初始提交。

## 使用方式

```bash
./document/customer-project/scripts/derive-customer-project.sh \
  --customer-code customer_code \
  --customer-name 客户公司名称 \
  --destination /绝对路径/customer-mall \
  --source-ref 已验收提交哈希
```

目标目录必须不存在且位于商城基座仓库之外。建议使用已经完成完整回归并记录在发版报告中的提交，而不是随意选择开发中的提交。

## 生成结果

- 独立 `main` 分支和一条“初始化客户独立项目”提交。
- `CUSTOMER_PROJECT_ORIGIN.json`：记录客户标识、来源基座版本、来源提交和派生时间。
- `CUSTOMER_PROJECT.md`：用非技术语言列出当前安全状态和下一步。
- 客户专用 `AGENTS.md`：阻止把客户制度推回基座或误用基座生产环境。
- 不设置 Git 远程，不生成 `.env`、证书、密钥或正式服务器目标。
- 默认奖金程序仍为 `CUSTOMER_BONUS_DISABLED`；客户制度未完成前不产生奖金。
- Android 和支付宝回调使用不可用的安全占位值，必须在客户资料确认后通过私有部署流程配置。

## 不会带入客户项目的内容

- 基座 `.git`、`AGENTS.md`、旧发布包和正式服务器目标。
- 任何 `remote-*`、`production-*` 历史发布脚本和基座 SSH/Systemd 配置。商城支付安全测试依赖的三份 Nginx/CSP 参考文件会保留，但基座域名会替换为不可发布的客户占位域名，且不附带证书部署或服务器连接脚本。
- 基座每日日志、发版报告、候选报告、审计截图和 XMind 文件。
- 本地依赖、构建产物、`.env`、证书、私钥和运行数据。

派生完成后，先人工创建客户自己的私有 Git 仓库并核对地址，再配置远程；然后冻结客户制度和验收案例。服务器、数据库、域名与密钥仍使用 `document/private-deploy/scripts/deploy.sh` 独立配置，不能由派生工具猜测。

## 同步商城基座公共修复

客户项目投入维护后，不重新复制文件夹，也不直接覆盖客户项目。使用基座仓库中的升级工具先做只读预检：

```bash
./document/customer-project/scripts/upgrade-customer-project.sh \
  --project /绝对路径/customer-mall \
  --target-ref 已验收的新基座提交 \
  --report /绝对路径/customer-upgrade-preview.md
```

预检要求商城基座和客户项目均无未提交改动，报告路径必须位于客户项目之外。工具会读取客户项目的 `CUSTOMER_PROJECT_ORIGIN.json`，用“旧基座、客户当前代码、新基座”进行三方比较：

- 只有基座修改的文件可以自动更新。
- 只有客户修改的内容保持原样。
- 双方修改同一文本文件时尝试三方合并。
- 同一路径冲突、客户删除但基座又修改、双方修改二进制文件时停止，不写入任何文件。
- 客户独有且基座不存在的制度、资料或 UI 文件不会被删除。

确认预检报告后，增加 `--apply` 正式写入。工具只更新客户工作区和来源清单，不会自动提交、推送、执行数据库迁移或发布。应用后必须查看 Git 差异，完成客户项目后端、公开商城、团队 H5、一体化 H5 和管理后台回归，再由客户项目独立提交与发布。

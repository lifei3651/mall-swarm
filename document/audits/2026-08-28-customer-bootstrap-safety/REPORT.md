# 新客户项目安全初始化审计

审计日期：2026-08-28  
本地候选版本：`1.0.96`  
线上版本：`1.0.95`（本轮未发布）

## 结论

新客户项目的首次初始化已收敛为“商城交易可运行、奖金默认关闭、演示内容不公开”。客户完成独立奖金制度开发和全流程验收前，系统只启用 `CUSTOMER_BONUS_DISABLED`；支付、履约和售后可以继续，订单不会产生奖金。

## 发现并修复的问题

- 原私有部署初始化只创建租户，没有建立奖金程序。全新数据库可能因找不到启用中的制度版本而阻止后续奖金协调流程。
- 基础数据库包含便于本地开发的演示分类、轮播、公告、商品和规格，首次部署后可能直接暴露在客户域名。
- 新租户默认展示配置曾沿用 PV 显示值，不适合作为尚未完成客户制度接入的通用交付默认值。

## 当前安全行为

- 全新私有部署只建立一个启用中的 `CUSTOMER_BONUS_DISABLED`。
- PV、团队业绩、奖金来源、奖金流水及其他内部经营展示默认关闭。
- 基座演示分类、轮播、测试公告、商品和规格全部转为后台草稿，不删除数据，方便开发参考。
- 初始化以“客户没有任何奖金版本”为首次执行标记；重复运行不会覆盖客户后续修改的展示、商品状态或奖金版本。
- 升级早期私有部署时，仅在该客户奖金版本为零时补齐关闭版本；只要已有任何客户制度，脚本不自动切换或替换。
- 部署后验收强制要求客户只能存在一个启用中的奖金程序，否则停止交付。

## 验证结果

- 真实 MySQL 8.4 全新初始化通过，结果为：租户 1 个、启用奖金程序 1 个且为 `CUSTOMER_BONUS_DISABLED`、内部展示 0 项开启、演示分类/轮播/公告/商品/规格 0 项公开。
- 同一初始化脚本连续执行两次，数据库状态保持一致。
- 在数据库中模拟客户把PV、一个正式分类和奖金程序改为自定义值后再次执行初始化，三项均保持为客户值（`1:1:CUSTOMER_CUSTOM_TEST`），证明升级不会重新套用基座默认值。
- 新租户服务测试验证后台创建客户时同步写入关闭奖金程序，PV、团队业绩、奖金来源和奖金流水均为关闭。
- 公共后端 14/14、分销后端 533/533，合计 547/547；失败 0、错误 0、跳过 0。
- 私有部署安全工作流、脚本语法和 Compose 校验 9/9 通过。

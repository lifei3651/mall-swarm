# 第七轮安全审查补充复核（1.0.66）

范围：用户补充的 S05、S06、S07、S08、S09、S11、C01、P04，以及 8 条无 `tenant_id` 的看板查询。方法：仅审查本地代码、配置与自动化测试；未访问线上、未执行攻击或数据写入。

## 结论

| 条目 | 结论 | 证据与处理 |
| --- | --- | --- |
| 8 条看板 SQL | 当前无需整改 | `dms_shop_member`、`dms_agent`、`dms_withdraw_record` 在当前“每客户独立数据库”架构中属于本部署全局数据；部署内多商户不拥有这些平台看板接口。未来若改共享数据库 SaaS，必须作为完整数据迁移项目补字段和全链路租户条件。 |
| S05 | 非漏洞 | `/distribution/commission/**` 由后台会话保护并要求 `commission:manage`，商户工作区被服务端阻止。这是平台按会员处理佣金的合法能力，不能改成管理员自己的 agentId。 |
| S06 | 非漏洞 | `/distribution/assets/**` 要求 `finance:read/manage`，商户工作区被服务端阻止；平台财务必须能按会员核账。 |
| S07 | 已加固 | 普通余额流水响应对登录账号和手机号脱敏；如果展示名回退到账号或手机号，同步脱敏。原始值仍可用于后端检索，不直接返回列表。 |
| S08 | 已修复 | `admin:read` 看板不再用收款实名兜底会员名称，待审核提现的收款实名只保留姓氏。 |
| S09 | 已修复 | 排行榜从 `selectAll + 每会员多次查询 + 内存分页` 改成单条聚合 SQL、数据库排序和 PageHelper 分页；新增业绩时间/目标代理和关系父级索引。 |
| S11 | 已修复 | 提现列表、按会员列表、待审核列表默认脱敏账号、手机号、银行卡和实名；完整单笔详情提升为 `finance:manage`，审核/打款页面按需读取详情。 |
| C01 | 非漏洞 | 订单号虽然保留时间前缀，但尾部是完整 13 位 base36 雪花 ID，并且所有订单读取、支付、售后都有会话归属校验。移除前缀不能替代授权，也不产生可量化风险下降。 |
| P04 | 已加固 | 服务端下单原本已重新计算价格；现进一步在购物车打开及结算前从商品详情接口覆盖本地价格、PV、库存、限购和商户信息，并明确以服务端结算为准。 |

## 安全边界

- 完整提现收款资料仅对 `finance:manage` 单笔详情开放；`finance:read` 列表只返回脱敏信息。
- 商品成交价、库存和限购始终以服务端校验为最终权威，浏览器本地数据不能改变订单金额。
- 本报告不把未来共享数据库 SaaS 的字段改造要求误报成当前独立部署漏洞；一旦产品架构改变，应重新建立全表租户模型并迁移历史数据。

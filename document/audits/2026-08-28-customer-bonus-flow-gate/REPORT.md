# 客户制度冻结与商城全流程交付门禁报告

日期：2026-08-28（Asia/Shanghai）

对象：App / 小程序公开商城 + 团队 H5 拆分基座（含可选一体化 H5 构建）

当前线上版本：`1.0.93`

本轮状态：线上 `1.0.93` 发布后的本地下一版本候选，未再次发版

## 一、结论

商城基座的客户奖金接入边界继续成立：基座只冻结订单与关系、接收客户程序返回的奖金结果，并统一完成落库、结算、钱包入账、退款追回和审计；客户奖金名称、比例、层级、复购、报单、等级与资格条件不写死在商城基座。

本轮补齐了客户项目派生后必须具备的一致性门禁：正常订单的奖金计算与退款处理都使用订单支付时冻结的同一个客户制度版本，后续切换当前制度不会改变历史订单口径；异步补算也使用任务自身的客户编号，不会回落到默认客户。

## 二、发现并修复的问题

### 1. 支付快照与奖金计算可能使用不同制度

支付流程原本先把当前客户制度版本写入订单关系快照，随后奖金服务又查询一次“当前启用版本”。若运营或部署在两次读取间切换制度，关系证据可能冻结制度 A，奖金却按制度 B 计算；退款又按快照中的制度 A 回调，形成历史口径不一致。

现已改为：

1. 正常支付订单从关系快照解析唯一冻结版本。
2. 同一订单出现多个冻结版本时停止计算。
3. 冻结版本在所属客户下不存在时停止计算。
4. 只有没有关系快照的历史导入或兼容调用，才回退当前启用版本。

### 2. 异步补算遗漏客户编号

异步奖金任务虽然保存了客户编号，但处理任务时调用了默认客户重载。现已明确传递任务所属客户编号，确保未来客户独立项目的补算、重试与审计仍使用自己的制度空间。

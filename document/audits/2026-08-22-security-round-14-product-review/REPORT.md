## 产品结论

原报告共 43 项。逐项核对后，12 组缺口或加固项成立并已处理；其余属于已有保护、旧脚本/旧结论、正确的安全降级、客户部署选择，或需要独立数据治理项目的架构建议。没有把“报告数量”直接等同于真实漏洞数量，也没有为通过扫描而破坏支付、SSE、历史账号或财务业务。

本轮的真实风险优先级为：资金与商户控制二次验证 → 数据库敏感信息明文 → 代理层入口收口。SSE 消息、固定账户哈希、外键/CHECK、全局 IP 白名单和金额字段统一等条目不具备当前可利用证据，不纳入本次补丁。

## 已修复

### 商户和财务二次验证

- 服务端强制覆盖商户新增/资料修改、保证金冻结/收款/释放、代商户提现、提现资料复核、驳回、开始付款、付款失败、风控冻结/恢复，以及财务风险规则保存。
- 管理后台统一调用现有 step-up 流程：重新验证当前管理员密码，签发 2 分钟有效、一次性消费、绑定管理员/HTTP 方法/完整路径的凭证。绕过页面直接请求同样会被服务端拒绝。
- “确认打款”继续使用接口原有 `adminPassword` 强校验；提现归档完成不重复要求密码，因为它只归档已确认付款的终态记录，不再次移动资金。
- 会员提现审核、管理员状态、会员状态/调级/移线、佣金结算、订单退款和售后退款在上一版已接入同一机制，本轮复核继续通过。

### 数据库敏感字段

- 代理身份证和银行卡、会员提现银行卡、商户银行卡、商户提现收款快照、ERP `app_secret` 和 `callback_token` 使用 AES-256-GCM 随机 IV 透明加解密，密文带版本前缀。
- 历史明文仍可读取；启用加密写入后按每批 200 条、每批独立事务迁移，条件更新保证中断可重试，日志只记录数量不记录敏感值。
- 生产启动要求独立 64 位十六进制随机密钥；私有部署脚本自动生成，Compose 只传给后端，交付清单要求密钥与数据库备份成对保管。密钥丢失或擅自替换会导致密文不可恢复。
- 新增迁移扩充密文字段容量。既有线上环境采用两阶段发布：第一阶段新程序以 `DATA_ENCRYPTION_WRITE_ENABLED=false` 验证读取和业务兼容；第二阶段改为 `true` 后迁移。迁移后只能回退到支持解密的兼容程序，不能直接使用 1.0.74 及更早的旧包。

### Nginx 与私有部署

- 正式域名配置不再把公网 IP 和 `_` 当商城域名；未知域名或直接 IP 的 HTTPS 请求由默认站点返回 404。
- 私有模板 `connect-src` 从任意 HTTPS 收紧为同源；`style-src` 不再整体允许行内样式，仅保留 Element Plus 布局所需的 `style-src-attr`。
- 私有部署请求体上限从 50MB 收紧为 6MB，与后端 5MB 文件、6MB 请求上限保持一致。
- 客户新部署强制开启敏感字段加密；部署预检会拒绝缺失/错误密钥或未开启加密写入。

## 不按误报修改的主要条目

- SSE 已有会话/权限、精确 CORS、全局和单用户连接上限、10 分钟重认证、25 秒心跳、有限队列及前端 4xx 停止重连；消息只含刷新信号，权威订单状态仍通过接口读取。
- 支付、会员、管理员、佣金和订单售后等高风险操作已有 step-up 或资金密码保护；“所有写操作都弹密码”会损害履约效率，也不能替代后端权限和状态机。
- 固定系统资金账户不可登录；H2 只用于隔离测试；旧基线测试账号和硬编码生成器密码已在上一轮清理，不重复报告为现存问题。
- 全局强加外键、CHECK、统一金额精度和后台 IP 白名单需要结合历史数据、客户网络和停机窗口单独设计，不能用一次局部补丁冒充已完成。

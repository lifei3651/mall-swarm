## 五、发现并修复的问题

真实沙盘首次执行发现：相同 `X-Idempotency-Key` 没有在 Redis 第一层被拦截。订单行锁和状态机仍保证只扣款一次、只生成一组奖金，因此当时没有资金损失，但重复请求保护缺少第一道防线。

原因是 `IdempotentAspect` 位于公共模块，不在分销应用默认组件扫描路径内；原单元测试直接实例化该类，未覆盖正式应用装配。修复为：

- 增加排在 `RedisAutoConfiguration` 之后的正式幂等自动配置；
- 仅在 `StringRedisTemplate` 存在时注册，测试环境不强依赖Redis；
- 登记 Spring Boot 自动配置清单；
- 新增真实配置顺序测试；
- 使用修复后的临时后端重新跑完整真实沙盘，确认相同请求号被拒绝且 Redis 幂等键实际生成。

此修复归入本地 `1.0.51` 待发布版本；线上后端程序仍为 `1.0.50`，没有在本次数据验收中静默覆盖。

# 第七轮安全审查复核与修复报告

审查日期：2026-08-21

范围：当前本地 `mall-swarm-app-h5` 仓库

方式：静态代码、配置与自动化测试复核；未访问线上、未执行漏洞利用、未修改业务数据

## 结论

原报告 22 项中，7 个报告条目含实际修复（S01/S08 指向同一佣金看板根因）、2 项适合进一步加固、1 项属于性能技术债，其余 12 项在当前代码或已确定的部署架构下不构成可利用漏洞。原报告将“每客户独立数据库”误按“多客户共享数据库 SaaS”审查，因此 S01～S04 的严重程度不能直接成立。

当前边界是：每个客户独立部署、独立数据库和密钥；一个客户商城内部的入驻商户使用服务端会话绑定的 `merchant_id` 隔离。`tenant_id=1` 是每套客户私有部署内的客户作用域，不接受前端请求头或参数切换。未来如果改为多个客户共用数据库，必须作为完整 SaaS 架构迁移统一补字段、唯一约束、索引、历史数据迁移和跨租户测试，不能只改几个 Mapper。

| --- | --- | --- |
| S01 | 部分成立 | 销售、财务、商品等看板查询原本已有订单租户条件；会员、代理和提现属于当前独立客户数据库内的平台数据。对确有 `tenant_id` 的佣金表补充显式租户条件，覆盖待结算金额、数量和最新佣金。 |
| S02 | 当前不成立 | 业绩表属于独立客户数据库内的团队数据，不存在多个客户共库。商户账号不能进入平台业绩功能；未来共享数据库 SaaS 化时需整体迁移。 |
| S03 | 当前不成立 | 提现记录属于独立客户数据库内的平台财务数据；接口受后台会话、权限矩阵和商户工作台隔离保护，不是任意会员可访问。未来共享数据库时整体迁移。 |
| S04 | 当前不成立 | 默认租户 1 是私有部署模型的明确设计，不从客户端解析租户编号，因此不能通过伪造请求切换客户。它不等于共享数据库的租户路由实现，也不应被用于共享数据库 SaaS。 |
| S05 | 不成立 | 佣金查询位于 `/distribution/**` 后台边界，需要管理员会话和 `commission:manage` 权限，商户账号被平台功能隔离拦截，不是“任何已认证用户”。 |
| S06 | 不成立 | 会员资产查询需要后台财务读取/管理权限；商户会话不能访问平台资产接口。按代理或会员查询是平台财务核账能力。 |
| S07 | 不构成越权 | 原始手机号和账号只在授权平台财务人员的核账列表中返回，未进入公开商城、普通会员或商户响应。保留是为人工核账，但仍受后台最小权限和操作审计约束。 |
| S08 | 部分成立并加固 | 最新佣金和待结算佣金已补显式租户条件；待提现属于当前独立客户数据库内的平台财务数据，且商户不能进入平台看板。 |
| S09 | 性能技术债 | 当前业绩排行存在全量代理加载和重复聚合，数据量大后会退化；不形成越权或数据泄露。应在获得真实规模指标后改为数据库聚合或按日增量快照，不在安全补丁中改变奖金统计口径。 |
| S10 | 成立，已修复 | 佣金列表的会员关键词、订单号和资产流水关键词/关联单号增加服务端长度上限，并启用参数校验，防止超长模糊查询。 |
| S11 | 不构成越权 | 银行账号只返回给有提现/财务权限的平台管理员，用于付款核对；普通会员、商户和公开接口不能调用平台提现列表。 |
| S12 | 已有保护并继续加固 | 导出原本已有后台认证、权限和通用 GET 限流；新增独立的经营报表导出限流，每个来源每分钟最多 5 次。 |
| C01 | 不成立 | 订单号不是简单递增值，而是时间部分加完整 13 位 base36 雪花编号；所有会员订单读取还会校验登录会员归属，知道订单号也不能读取他人订单。 |
| C02 | 不成立 | 支付宝通知进入业务前使用官方 SDK 验证 RSA 签名，并核对 `app_id`、金额、订单状态；交易行锁、确定性业务号和状态条件提供重复通知幂等。 |
| C03 | 不成立 | 模拟支付默认关闭、生产配置明确关闭；生产安全启动门禁发现启用模拟支付会拒绝启动。 |
| P01 | 不成立 | 前端金额只用于提前提示是否需要短信；下单和余额支付时后端重新读取商品、SKU、数量及运费计算权威金额，再以权威金额执行短信阈值验证。 |
| P02 | 成立，已修复 | 收货人最多 30 字、详细地址最多 200 字、整段粘贴最多 500 字；前端和服务端同时校验。 |
| P03 | 成立，已修复 | 订单备注统一限制为最多 500 字，前端和服务端同时校验。 |
| P04 | 不构成资金漏洞 | 本地购物车只能影响当前浏览器展示；提交订单只发送商品、SKU 和数量，服务端重新计算售价、库存和金额。 |
| P05 | 成立，已修复 | 跳转地址管理页时不再把姓名、电话和完整地址写入 `sessionStorage`，只暂存地址编号、支付方式和备注。 |
| P06 | 条件风险，已修复 | 兼容旧版登录时只把遗留 Token 临时放在页面内存，模块加载后立即删除 `localStorage` 副本，换发 HttpOnly Cookie 后清空内存。迁移失败的旧会话可能需要重新登录一次。 |
| P07 | 加固完成 | 支付密码仍只在提交期间存在页面内存中；支付成功、失败或关闭弹窗都会立即清空支付密码和设置密码表单。 |

## 本轮代码改动

- 看板佣金统计和最新佣金增加服务端当前租户条件，并增加跨租户数据不进入看板的集成测试。
- 佣金、资产流水搜索参数增加服务端长度限制和参数校验。
- 后台经营报表导出增加每分钟 5 次的独立限流。
- 收货人、地址、订单备注增加前后端一致的长度边界。
- 结算草稿不再保存完整收货隐私信息。
- 旧版 Token 从持久化存储迁移为一次性内存兼容，并在换发 HttpOnly Cookie 后销毁。
- 支付密码和设置密码字段在完成、失败或关闭弹窗时统一清空。

- S09 业绩排行性能优化需结合客户真实代理规模、查询频率和统计口径设计增量表或数据库聚合，属于后续规模化优化，不影响当前权限和资金正确性。

# 第九轮安全与产品链路复核报告

审查日期：2026-08-22

审查对象：App / 小程序公开商城 + 团队 H5 拆分版，并兼容一体化 H5 构建

审查方式：本地代码、配置、迁移、自动化测试和生产构建；未访问或修改线上业务数据

## 一、结论

报告中的 43 项并不等于 43 个可利用漏洞。逐项映射真实请求链路后：30 项完成代码或产品链路整改，9 项经现有保护或产品约束确认不应按报告方式修改，4 项本身是正面结论。最高优先级的真实问题是运费模板的服务端客户范围、关键配置权限过粗、关键管理动作缺少业务审计上下文，以及前端会话提示与路由体验不完整。

本轮没有发现可以绕过后端身份认证、直接取得管理员权限或突破商户数据隔离的新路径。商城前端的本地会话标记和后台权限展示都不是服务端授权依据；本轮仍进一步移除了本地标记对 H5 已登录状态的决定权。

## 二、产品整改总览

| 产品域 | 本轮结果 | 对运营的实际变化 |
| --- | --- | --- |
| 登录与路由 | 已整改 | 会话必须经服务端恢复；未登录、无权限、404 都有明确页面或提示；重复登录跳转可恢复 |
| 敏感表单 | 已整改重点页面 | 商城资料和商品编辑存在未保存内容时，关闭、刷新、切换路由或关闭弹窗会二次确认 |

### 2. 运费模板与物流

| 编号 | 结论 | 处理与依据 |

| T002 | 已验证并修复 | 商品配置读取和结算运费重算都使用商品/当前会话客户范围，不接受调用方扩大范围。 |
| T003 | 已修复 | 模板仍被商品引用时禁止停用，并提示先为商品更换模板，避免商品突然无法下单。 |
| T004 | 报告风险不成立 | 发货服务先锁订单，再校验状态、物流单重复和剩余可发数量；粗粒度接口幂等会错误阻止合法分包发货，故保留现有订单级并发控制。 |
| T005 | 已优化 | 同一模板内规范化后完全相同的地区路径禁止重复；省/市不同粒度继续允许，按更具体规则优先，这是产品能力而不是冲突。 |

| T010 | 已修复 | 满额包邮模板的未达门槛运费必须大于 0，避免“配置了门槛但实际始终包邮”的误配。 |

## 四、安全不变量与合法业务

修复后必须同时成立：

1. 运费模板 ID 即使被猜到，也只能在当前客户范围读取和用于结算。
2. 商城资料运营人员不能修改奖金口径或 ERP 密钥配置，除非另有对应权限。
3. 本地存储只能改善页面体验，不能建立会员或管理员身份。
4. 审计记录不得包含密码、验证码、Cookie、支付私钥或完整会话令牌。
5. 合法的省/市分级运费、同单分包发货、商户履约和历史模板留档继续正常工作。

# 自动收货、物流异常与多包裹履约门禁报告

日期：2026-08-28

状态：本地增量已验收，待后续版本统一发布

基线：`VERSION 1.0.94`，线上仍为`1.0.94`

## 产品结论

- 自动确认收货属于订单履约的系统必需能力，不进入商城视觉装修工作台，也不提供客户运营侧随意关闭的开关。
- 默认规则为订单完整发货满15天且没有处理中售后时自动确认收货；分批发货期间不提前起算，以最后一批发出、订单正式进入待收货的时间为起点。
- 用户提交“物流停滞 / 未收到货”或“拒收 / 退回商家”等售后后，处理中售后会阻止自动确认收货。售后撤销或关闭后，下一轮扫描才能继续处理。
- 使用“确认收货后N天”口径的客户售后制度，从真实手动或自动确认收货时间重新起算，不在发货时提前消耗售后期。
- 当前基座没有已启用的真实物流服务商轨迹回调，因此不根据模拟轨迹猜测拒收、滞留或异常；本阶段提供清晰的会员自助入口。客户后续接入真实物流服务商时，再按该客户通道扩展自动拦截。

## 本次完成

### 自动确认收货

- 新增独立分布式定时任务，每10分钟扫描一次，每批最多200单；同一任务跨实例互斥，单个异常订单不影响其他订单并保留下轮重试。
- 候选查询和逐单事务均复核客户范围、订单状态、完整发货时间和处理中售后，避免并发扫描、并发售后或重复任务造成重复确认。
- 自动确认后写入真实收货时间、锁定商户结算资格、记录`AUTO_RECEIVE`操作日志并触发现有订单收货通知链路。
- 默认15天可通过客户独立服务器的受控部署参数调整，但不能设置为关闭；服务端强制限制在1至365天。

### 会员端物流与售后

- 订单详情展示预计自动收货时间，并明确提示未收到、物流停滞或拒收时应先提交售后，处理中不会自动确认收货。
- 新增“物流异常 / 拒收”快捷入口及两个标准原因，统一使用仅退款申请，仍由既有售后审核、凭证和退款流程处理。
- 订单列表同步展示预计自动收货时间和“未收到 / 拒收”入口，减少会员等待到期后才发现订单已自动收货的风险。

### 多包裹履约

- 订单详情逐包展示承运商、运单号和本包裹件数，每个包裹都可独立查询与复制运单号。
- 管理后台原有多包裹明细继续逐包展示件数，并新增只读预计自动收货时间，方便客服处理物流异常。
- 多包裹的自动收货起点仍是整单完整发货时间，不以首个包裹时间提前起算。

## 关键边界验收

| 场景 | 预期结果 | 结果 |
| --- | --- | --- |
| 待发货或部分发货 | 不自动确认收货 | 通过 |
| 完整发货未满15天 | 保持待收货 | 通过 |
| 已到期但存在处理中售后 | 阻止自动收货 | 通过 |
| 售后撤销后再次扫描 | 满足条件时确认收货 | 通过 |
| 同一订单重复扫描 | 不重复确认、不重复记账 | 通过 |
| 自动确认后的售后期 | 从实际收货时间起算 | 通过 |
| 多包裹订单 | 逐包展示数量、查询和复制 | 通过 |
| 尚无真实物流回调 | 不伪造异常状态，保留自助售后入口 | 通过 |

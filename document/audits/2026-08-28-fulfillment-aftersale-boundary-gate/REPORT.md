# 分批履约、售后幂等与商户隔离门禁报告

日期：2026-08-28（Asia/Shanghai）
仓库：`mall-swarm-app-h5`
分支：`codex/app-h5-split`
基线：线上与`VERSION`均为`1.0.94`
状态：本地下一版本候选，未发版

## 结论

本轮继续按“稳定商城基座”的真实经营流程审计分批发货、部分退款、退货重复操作、库存回补和商户售后权限。确认并修复三处组合状态问题，同时把既有商户隔离门禁补成自动化验收：

1. 订单先发出部分商品、再退款剩余未发数量时，原订单可能一直停留在“待发货”，导致会员无法确认收货。现在每次退款完成后都会按“原下单数量－累计批准退款数量”重新计算应发数量；已有包裹数量已经覆盖应发数量时，订单自动进入“已发货”。支付宝退款则继续等待渠道成功后再同步订单状态。
2. 分批发货记录已经存在但整单订单尚未进入“已发货”时，旧逻辑可能把订单误判为从未发货并退还原运费。现在运费判断同时核对订单状态、旧物流字段和真实包裹记录；只要已有任何发货包裹，原发货运费即锁定不退。
3. 完全未发货的“仅退款”此前不会在统一售后完成流程中回补所选商品库存，而后台取消订单又在外层单独回补，两个入口口径不一致。现在库存和秒杀名额统一由退款完成事务处理：完全未发货的仅退款、或商品实际退回时，按本次售后选中的商品与规格精确回补一次；已有真实发货且没有退货时不回补，避免把仍在消费者手中的商品重新变成可售库存。平台取消不再重复执行第二次回补。

退货物流重复提交相同公司和运单号时直接返回原记录，不改写首次寄回时间；商家确认收货退款完成后重复提交也直接返回完成结果，不会再次退款、回补库存、冲销奖金或冲回商户货款。跨商户售后列表、凭证、审核和确认收货仍按当前商户编号隔离，猜测其他商户售后单编号会被拒绝。

## 组合门禁

| 场景 | 当前结果 |
| --- | --- |
| 一单拆多个包裹 | 允许；累计发货数量不得超过扣除已退款后的可发数量 |
| 相同包裹重复导入/ERP回调 | 按订单、物流公司和运单号幂等跳过 |
| 售后处理中继续发货 | 阻止；售后取消、驳回或完成后再按剩余数量继续 |
| 先部分发货，再退剩余数量 | 自动把订单同步为已发货，会员可以确认收货 |
| 先部分发货，再整单退款 | 原运费不退；退款完成后订单关闭 |
| 完全未发货，仅退款 | 按本次售后商品与规格精确回补库存一次，秒杀名额同步释放 |
| 已有真实发货，仅退款且商品不退回 | 不回补库存，避免实物未回仓却重新可售 |
| 相同退货物流重复提交 | 幂等返回，不改写首次寄回时间 |
| 已完成退货再次确认收货 | 幂等返回，不重复退款或回补库存 |
| 支付宝退款等待渠道结果 | 渠道成功后才关闭整单、回退资格或同步分批发货状态 |
| 商户访问其他商户售后 | 列表、凭证、审核、确认收货全部拒绝 |
| 平台人工取消/退款 | 仍只允许平台管理员；商户工作台不能调用 |

# 第十三轮安全审查 · 产品与代码复核结论

审查日期：2026-08-22

审查范围：App / 小程序公开商城 + 团队 H5 拆分基座（含可选一体化 H5）

边界：只检查和修改本地仓库，不访问线上、不执行攻击、不修改业务数据。

## 总结

原报告 44 项中，确认并修复/加固 29 项；10 项经现有代码证据确认不成立或属于正确设计；5 项属于客户部署策略或需要统一密钥管理的数据安全架构，不适合用局部补丁冒充修复。最关键的改造是把后台敏感操作从“页面确认框”升级为服务端强制的一次性二次验证，并清除初始化 SQL 中的固定账号、测试会员和硬编码数据库凭证。

## 逐项结论

### 后台敏感操作二次验证

| 编号 | 结论 | 处理 |
| --- | --- | --- |
| 2FA-001～014 | 已修复 | 管理员状态/解锁、会员状态/解锁/调级、移线、商户控制、取消退款、售后退款、提现审核、佣金结算、外部团队迁入、配置恢复全部由服务端强制二次验证；直接绕过页面调用接口同样会被拒绝。 |

二次验证只签发凭证，不单独污染业务操作日志；真正产生影响的接口继续记录完整业务审计。读取、发货和客服备注等正常高频操作不增加无意义密码弹窗。

### SQL、初始化与敏感数据

| 编号 | 结论 | 处理 |
| --- | --- | --- |
| DB-001/002/005/012 | 已修复 | 旧 `mall.sql` 删除全部 1653 条账号和业务 `INSERT`，只保留带醒目警告的历史结构参考。 |
| DB-003 | 已修复 | 当前基线和历史升级 SQL 均不再创建固定管理员、静态盐或已知哈希。新增交互式 `bootstrap-admin`，仅管理员表为空时可执行，密码不进入文件或命令行，首次登录强制改密并迁移 BCrypt。 |
| DB-004 | 已修复 | 删除 Git 中的 root/root 代码生成凭证；真实代码生成配置改为本地忽略文件，示例要求本机最小权限专用账号。 |
| DB-006 | 架构建议 | “全局无外键”等同于漏洞的结论不成立。当前关键状态靠事务、行锁、条件更新、唯一约束和业务审计保持完整；一次性给全部历史表补外键会锁表并可能破坏合法历史数据，需作为独立数据治理工程。 |
| DB-007 | 已加固 | 基线明确标为“只用于全新空库”，唯一部署入口仅在首次空数据卷自动执行；旧结构文件醒目标注禁止生产执行，升级统一走版本迁移和预备份。 |
| DB-008 | 架构加固项 | 身份证和收款账户属于受控财务数据，页面、列表和日志已经分权、脱敏；数据库字段级加密必须连同客户 KMS、密钥轮换、备份恢复和查询能力统一设计，不能只加密两列后留下更大的不可恢复风险。客户交付仍应使用加密云盘、加密备份和最小数据库权限。 |
| DB-009 | 已修复 | 旧结构参考中的 `ums_admin.password` 改为非空；当前实际管理员表原本已非空。 |
| DB-010 | 正确兼容 | 旧 SHA-256 盐只用于历史账号登录时的一次性校验，成功后立即迁移 BCrypt；新账号和改密均使用 BCrypt。删除会导致合法历史用户无法登录。 |
| DB-011 | 已修复 | 7 处无效字符集 `utf8mb4mb4` 统一修正为 `utf8mb4`。 |
| DB-013 | 架构建议 | 金额、状态、编号等关键边界已有 DTO、服务和数据库唯一/条件约束；不对所有表盲目补 CHECK，以免与 MySQL 版本及业务状态演进冲突。 |

## 补充：RR 旧快照与新规则版本的并发读取

使用同一缓存 MySQL `8.4.10`，独立临时容器 `mall-direct-referral-version-20260930`（`--network none`、端口绑定 `{}`、1 GiB tmpfs、`--rm`），只导入仓库基线与两个合成租户。两条真实 MySQL 连接均显式使用 `REPEATABLE READ`。

T1 首先普通读取启用版本 910001，建立并保持同一事务快照。用无缓冲客户端及 FIFO 明确等待该读完成；T2 才锁定租户 900201、停用旧版本、插入启用版本 910002 并提交。同步确认 T2 `COMMIT` 完成后才继续 T1，未靠固定等待时间猜测事务先后。

| T1 在原事务中执行的读取 | 实际结果 |
|---|---|
| 首次普通读当前启用版本 | `before_plain=910001` |
| T2 提交后锁租户 | `t1_tenant_lock=900201` |
| 与 `selectActiveByTenantIdForUpdate` 相同筛选/排序的锁定读 | `active_lock=910002` |
| 与普通 `selectById` 相同租户/ID 筛选的快照读 | `new_plain_count=0`，新行不可见 |
| 与新增 `selectByIdForUpdate` 相同租户/ID 筛选的锁定读 | `new_id_lock=910002`，新行可见 |
| 再次普通读启用版本 | `old_plain_active=910001`，仍是旧事务快照 |

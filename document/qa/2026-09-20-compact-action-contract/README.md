# 商城普通操作按钮共用合同审查

日期：2026-09-20  
范围：微信小程序、公开/团队/一体化 H5 的订单列表、订单详情及两端共用界面门禁。  
状态：源码与自动验证完成；未发布、未上传微信开发版。

## 审查步骤与结论

1. **竞品订单详情参考：健康。** 用户提供的参考图中，查看物流、还想买、再买一单等普通操作随文字收宽、同排右对齐；复制只占一个小文字按钮。参考图含个人与订单信息，仅当场查看，不复制进仓库。
2. **原小程序订单列表：不通过。** 三枚操作被页面布局挤成两行，按钮接近半屏宽；主次层级过重。根因是共用层给订单按钮设置了可伸缩固定基准宽度和`64rpx`高度，仍允许单页形成大按钮。
3. **原小程序订单详情：不通过。** “查看物流 / 复制单号”纵向堆叠为固定宽胶囊，底部操作使用`flex:1`平分；复制不符合文字辅助操作定位。
4. **共用合同修正：通过。** 普通操作由`ui-action-button`统一为`56rpx / 26rpx / 24rpx`，宽度随文案；`ui-action-bar`和`ui-action-group`强制单行右对齐；`ui-copy-action`负责小型文字复制。H5使用`28px / 13px / 12px`等比规则。
5. **订单列表与详情迁移：通过。** 两端列表、物流操作、订单号/运单号复制、详情底部操作和小程序售后记录操作改用同一语义组件；“去评价”降为次操作，付款和确认收货保留为唯一主题色主操作。

## 自动验证

- 微信小程序：511项全量测试通过；工程结构、JavaScript、HTTPS、H5同源与共用界面门禁通过。
- 商城H5：176项全量测试通过；公开、团队与一体化三种生产构建及各自边界检查通过。
- 差异检查：`git diff --check`通过；全局扫描未发现订单普通操作恢复`64rpx`、固定大宽度、均分按钮或主题色“去评价”。

## 防回退门禁

- `scripts/check-storefront-ui-contract.mjs`精确核对两端尺寸、内边距、字号、按文案收宽和单行右对齐。
- 门禁拒绝恢复固定宽度的`ui-utility-button--wide`。
- 订单详情中任何包含“复制”的按钮必须使用`ui-copy-action`。
- 订单列表中“去评价”不得使用主题色主按钮。
- 页面仍可控制业务内容和留白，但不得用`!important`抢回共用按钮的宽高、颜色、圆角或阴影。

## 证据边界

- 当前截图证据来自用户本轮明确提供，足以确认原按钮比例、换行和层级问题；图片含隐私信息，未保存到仓库。
- 自动测试可证明组件引用、尺寸合同和业务绑定没有丢失，不能代替微信真机的字体缩放、按压态与弱网操作验收。
- 本轮不改接口、订单状态、支付、物流、售后或客户数据，不改`VERSION`，不部署、不上传、不提审。

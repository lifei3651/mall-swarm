## 安全修复与影响

按 Codex Security 修复流程完成一轮独立边界调查、主实现、一次新的只读绕过/回归复审；复审确认的两项历史数据缺口已在本轮继续补齐。原两个输入问题修复结果：`fixed`（本地验证，不代表线上已修复）。

- 普通订单、报价、活动和内部预留提交，在查商品/加锁前拒绝超过 200 行的订单和不合法数量；安全累加拒绝整数溢出。不悄悄截断、不把错误数量改成 1，也不把前端 99 件交互限制变成后端批量业务限制。
- 用户售后与后台退款对重复商品数量做溢出检查，拒绝负数、零和累计越界；保留合法重复项合并、部分退款及零元赠品的正数量处理。不把新订单的 200 行限制套用到历史售后。
- 售后审批、本地账务、库存回补、渠道发起前与渠道完成事务均检查明细；生产 Mapper 逐条检查历史保留数量、订单/商品/规格归属及每个原订单项的累计数量。不能用负行与正行抵消后得到的“正常总数”绕过，也不能审批正数但超过原购买数量的旧记录。
- 异常旧记录会停止继续退款并要求人工核查。未查询线上是否存在此类记录，未自动清理、纠正或重放任何历史交易。未证明原问题会导致超实付金额退款，不能夸大为无限盗款。
- 扩充微信登录临时代码、昵称及头像字段日志脱敏；新增头像不进入公开商品媒体目录。没有新增 AppSecret、支付密钥、密码、验证码或地址草稿的客户端持久化。
- 小程序 API、图片上传和私有头像下载使用 HTTPS；密码和验证码沿用既有额外应用层加密，不可用时失败关闭。头像、昵称、地址不是密码，不声称都使用了额外应用层密文；开发工具能看见请求内容不等于公网明文传输。

本轮没有改 H5 页面源码。订单/退款/日志/私有头像属于共享后端，发布后 H5 同样受新校验保护；因此不能说对 H5 完全没有影响。头像需要配套后端发布，不能只上传小程序就认为功能已经生效。无新增数据库表或迁移、无支付/消息运行开关改变。

## 微信后台必须配套处理（本轮未代为提交）

针对当前小程序 AppID `wxd26e0a4e41df392b`；客户派生项目必须改为客户自己的 AppID 与域名，不能复制本基座身份。

1. 开通 `wx.chooseAddress` 对应接口；不要批量开通定位、后台定位等未使用能力。代码 `requiredPrivateInfos` 已声明 `chooseAddress`。
2. request、uploadFile、downloadFile 合法域名配置实际 API 域名；本基座为 `https://lingqimall.com`。若客户使用独立存储/媒体域名，按真实调用增加，不添加未知域名或关闭域名/证书校验。
3. 微信隐私指引选择采集信息，并按实际用途补充：手机号（账号注册/绑定及订单联系）、头像/昵称（可选账号资料）、收货地址与收货人姓名/电话（保存地址和配送）、用户主动选择图片（可选售后凭证）。具体信息类型名称以后台可选项为准；若头像计入用户选择的照片，清楚注明“头像”用途。不得申报精确位置、通讯录等未使用信息。
4. 本轮没有新增第三方客户端 SDK；头像和地址使用微信原生能力。仍应依据实际全量依赖核对原有第三方服务/SDK，不因本轮未新增就宣称整个商城无第三方服务。
5. 将真实履约商家、物流、支付等接收方及客服联系方式维护在商城完整隐私政策中，匹配实际处理方式。不要空泛承诺不向任何第三方提供信息。保存期限与既有资料处理机制保持一致，不随意写 0 天。
6. 修改后的微信隐私指引、接口权限和应用代码一起真机验收。平台授权与商城已有协议不是同一份授权记录；本轮保留原登录协议版本兼容旧客户端，新增可选资料由微信独立授权管理。

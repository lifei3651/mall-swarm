# 活动信息流版：后台与小程序同步验收

2026-09-06，Codex；修改基线 `8d26dc93`，属于 `1.0.132` 本地候选。本批不部署、不上传、不保存线上配置。

## 问题与修复范围

后台装修预览原先只读取管理商品，给所有商品套一条活动示意文案；原生首页却独立渲染“限时活动 / 查看全部”，空数组也保留标题。H5 已经采用匹配商品的活动价、倒计时和活动入口，因此这次沿用该交互规则，不重做 H5。

| 场景 | 后台装修预览 | 小程序首页 |
| --- | --- | --- |
| 活动信息流版 | “整体版型”“首页模块”都展示限时活动来源、管理入口、刷新、匹配数量 | 活动标记出现在匹配商品卡上，不额外插入空活动栏 |
| 进行中 | 真实活动价格、结束倒计时、“去抢购” | 同展示规则，进入对应活动页 |
| 未开始 | 开始倒计时、“去看看” | 同展示规则，能查看活动但下单仍由原服务端校验 |
| 没有活动、已结束、关闭、售罄、商品下架 | 不套活动示意；恢复普通商品价格/入口 | 清除旧活动价和标记，保留普通商品与原加购流程 |
| 活动读取失败 | 明确失败状态并中央弹窗，不伪装成没有活动 | 中央提醒并提供重试，普通价格展示，不保留过时活动价 |

两端使用公开 `/shop/products`（前20件，默认排序）及 `/shop/flash-sales`。H5 同用公开接口，但目前首页取60件，不能称三端整页商品数量完全一致。后台活动展示与小程序使用契约测试保持一致的纯函数副本；不引入跨发布工程的运行时依赖。刷新、关闭/切换版型的晚响应有版本保护，活动租户不匹配不会用于预览。

保存装修不创建/启用活动、不修改活动价格、库存或限购。管理链接复用 `/tenant/flash-sales` 与原有权限守卫，新标签打开，保留未保存装修。活动提交仍走原活动报价/下单接口，未更改财务或资格规则；普通商品仍走之前的共享加购/累计限购逻辑。

倒计时只向原生视图更新变动的活动字段，避免每秒重传整个商品数组；全部活动结束或页面隐藏停止计时。活动页顺手修复原生不支持的嵌套 `wx:key="activity.id"`，改为稳定顶层编号。

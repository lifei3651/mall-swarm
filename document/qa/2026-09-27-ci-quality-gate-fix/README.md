## 原因与修复

1. **通知时间口径不统一。** 原通知测试用机器默认时间，发送器用 Asia/Shanghai。UTC 隔离 H2 复现原 7 项中 5 失败、1 错误、1 通过，与 GitHub 一致。同类扫描发现实际任务创建、授权状态、回执和微信通知显示也用了默认时间；统一为 `NotificationTime`。保留所有幂等、预算、授权和过期拒发条件，不通过将 CI 强制设置北京时间来掩盖问题。CI 全量固定 UTC，另跑北京时间通知回归。
2. **小程序跨端对照依赖漏装。** `full-parity.test.mjs` 直接导入 H5 地址解析器，后者依赖 `element-china-area-data`。独立矩阵任务只安装小程序依赖，缺少 H5 的 node_modules。现在仅在小程序任务内用 H5 锁文件安装对照依赖，保留跨端一致性测试；本地说明同步补齐首次安装步骤。
3. **客户证书预检不兼容新 Python。** 旧脚本调用 Python 3.12 删除的 `ssl.match_hostname`，把接口异常吞成域名不匹配。改为 OpenSSL 原生 `x509 -checkhost`，同时要求退出成功和明确匹配结果（部分 OpenSSL 在不匹配时仍退出 0）。不自写通配符算法、不禁用校验；缺证书、错误域名、不支持该功能均拒绝。运行要求明确为 OpenSSL 1.1.1+/3.x，Mac 自带 LibreSSL 不能代替。

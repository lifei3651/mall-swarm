# 秒杀模块关闭态：后台活动写入门禁

日期：2026-09-26（Asia/Shanghai）。本轮只处理通用基座的一个 P1-16 子缺口；线上服务器和微信体验版仍按 1.0.167 记录，本轮没有形成新候选或发布。

## 发现与修复

- 已有的秒杀总开关会隐藏顾客活动列表并拒绝秒杀下单，但后台独立的“更新活动状态”接口未检查总开关；停用的旧活动仍能被重新标为启用。后台活动页也始终显示“新建/启用”。
- 服务端现在让新建、编辑与重新启用活动先锁定租户配置并验证总开关，与后台切换开关的写入串行；关闭时仍可查看历史活动、停用旧活动。顾客下单门禁保持原有规则。
- 后台活动页读取同一公开业务配置；读取失败时禁用新建/启用并提供重试，关闭时展示说明，停用旧活动仍可操作。服务端校验不依赖页面状态。
- 关闭后既有秒杀订单的取消和退款仍须回补库存；本轮没有删除历史活动或订单。

## 本地证据和限制

- H2 定向覆盖关闭后新建/重新启用被拒、旧活动仍可停用，以及关闭后已支付订单取消与库存回补。后端与公共模块全量 850/850、失败 0；后台 221/221，管理端生产构建和差异检查通过。
- 未在隔离 MySQL 中并发切换开关/抢购；顾客秒杀提交与总开关切换的严格并发边界仍需单独验证。也未执行服务器部署、微信上传或真实活动/退款验收。
- P1-16 仍开放；本项不证明余额、多商户、复购与奖金可任意组合，更不改变其他 P0 的验收要求。

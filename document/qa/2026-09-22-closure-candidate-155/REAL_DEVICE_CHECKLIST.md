# 商城收口真机检查清单

> 历史提示：`1.0.155` 已在 S/W 前因权限合同缺口作废。本清单可继续用于 `1.0.154` 现状排查，但不得再用于关闭 `1.0.155`；后续候选验收以 `1.0.156` 的独立清单和平台回执为准。

本清单区分“现状排查”和“候选验收”。没有先证明手机实际打开的版本，截图只能作为问题线索，不能登记为 R（真实验收）通过。

## 1. 每次验收先固定版本证据

1. 平台回执必须能对应到版本、产品提交和固定上传工程聚合哈希。
2. 微信后台必须明确把对应开发版设置为体验版。
3. 手机从该体验版二维码进入，并截图保留“体验版/版本”标识、时间和页面。
4. 手机页面不要求展示 Git 提交；证据链使用“上传回执 → 体验版绑定 → 体验二维码进入”关联到提交。

当前微信平台开发版仍为 `1.0.154 / a8f86f2e`，体验版尚未确认指向。`1.0.155 / 93059809` 没有上传，也没有部署对应服务器和第 41 条迁移，现已作废。因此当前真机操作默认只作现状排查，不能关闭任何新候选的 R。

## 2. 现在可做的无资金现状排查

以下检查不需要付款；若能先证明打开的是 1.0.154 开发/体验包，可登记为 1.0.154 历史证据，但最终仍需在替代候选复验：

- 术语：只出现“普通商城”“复购区”，不出现“报单区”“客户定制奖金”；可用缺规格、库存不足等无资金错误提示检查文案。
- 设置中心：超级管理员检查独立侧栏、面包屑、旧链接跳转和直达链接。没有其他角色账号时，不得写成逐角色完成。
- 个人资料：反馈账号应显示手机号商城账号，不再显示“尚未设置”；邀请人明确显示“无/暂无”，与正式库 `NONE` 一致。
- 余额读取：进入确认订单页，余额应正常读取且不弹“暂不可用”，停在提交付款前。
- 数量输入：首页、分类、购物车手工输入数量，核对加减、空值恢复、库存/限购提示；只计 1.0.154 现状回归。
- 既有订单和物流：可用于继续发现问题，不得据此关闭替代候选的订单列表、订单详情或物流闭环。

## 3. 必须等替代候选完成 S/W 后验收

顺序固定为：先完成替代候选耐久留存，再部署服务器和第 41 条迁移（S），之后上传同一候选的微信开发版并设置体验版（W），最后真机 R。禁止让新候选前端连接 1.0.154 后端进行验收。

- 订单列表五种以上状态：紧凑高度、逐件大图、名称、规格、数量、零售价、实付、真实服务标签、右上复制、同排操作和主操作最右。
- 订单详情：状态/送达时间、本人结算收入、物流与脱敏收货人、大图商品、金额、全部订单信息、再买一单。
- 服务标签：历史订单只显示第 41 条迁移回填结果，新订单保存下单时快照；未配置的不显示。
- 售后与评价：售后进行中不进入待评价列表、角标或评价按钮；终态 `1/2/3` 才恢复。
- 本人结算收入：按追回后的当前净额显示，全额追回为 0，待结算不重复扣减。
- 同一候选的支付、订单、退款、售后、发货、物流、余额、奖金和资金九链路。

## 4. 逐角色账号前置条件

验收前给账号使用固定标签并记录脱敏标识、客户、商户和权限快照：

| 标签 | 角色 | 最小用途 |
|---|---|---|
| `SA` | 平台超级管理员 | 全部设置、旧链接、审计与拒绝边界 |
| `OP` | 平台自定义运营角色 | 只授予指定设置/业务权限，验证菜单、直达接口和越权拒绝 |
| `MO` | 商户负责人 | 本商户商品、订单、发货、售后、财务和员工授权 |
| `MS` | 商户员工 | 本商户已授予能力；不得进入平台设置或其他商户数据 |
| `A` | 具备邀请资格的会员 | 生成本人有效邀请并验证分享参数 |
| `B` | 从未注册的新手机号 | 首次注册确认后绑定 A 一次 |
| `C` | 已注册会员 | 打开 A 的邀请后原关系保持不变 |

反馈账号当前没有推广资格、邀请关系为 `NONE`，不能把它当作 `A`。邀请测试会写入账号关系，执行前必须先保存 A/B/C 的前置关系；没有合格账号时标记“未验证”，不得临时补绑或绕过资格。

## 5. 每项回执字段

每条 R 至少记录：候选版本、上传回执编号、体验版绑定时间、手机型号、系统和微信版本、账号标签、订单号（如有）、金额（如有）、开始/结束时间、预期、实际结果、截图或视频位置、后台/数据库核对结果、验证人和结论。

付款、退款、售后、发货、账号关系或任何真实资金/外部平台写入，仍需在执行时单独确认；本清单不扩大操作授权。

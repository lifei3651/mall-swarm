# 1.0.171 微信地址导入返回稳定性

日期：2026-09-28。接用户真机反馈“微信导入添加地址返回列表刷新两次”。本轮仅修当前待发布源码，不生成新的候选包或操作微信审核。

## 原因与修复

- 小程序保存微信地址后会GET回读列表；如果微信选择页的onShow晚于整个导入结束，原有saving/importing防重标记已经释放，会再GET一次。自动测试模拟选择、保存、回读、完成四个返回时点，旧代码在完成后的返回复现额外请求。未采集用户手机运行日志，不将模拟时序等同于真机抓包。
- 原WXML以loading分支替换整个已有列表，每次回读都会隐藏再显示；首次导入也有showForm关闭后、loading开启前短暂进入空态的路径。
- onHide仅在导入中记录当前账号的返回标记，onShow消费这一次标记。普通离开后再返回、换号仍正常读取；不用时间窗口或永久跳过刷新。
- 有旧地址时保留列表，服务端回读后更新；没有地址且正在导入/保存时显示等待态，不先闪“还没有收货地址”。旧列表刷新时按钮禁用，编辑处理也检查忙碌/错误状态；读请求中登录失效清空旧地址及表单，旧请求不能覆盖新账号的新列表。
- 保存只提交一次；不改默认地址规则、服务端保存接口、隐私授权、取消行为或结算选择模式。已保存但回读失败仍提示不要重复导入，并支持只读重试。
- 同类检查：小程序微信导入集中于地址页，结算页调用同一地址页选择；H5地址页使用onMounted且不调用微信chooseAddress，不改无关页面。

## 已处理的可复核缺口

1. 秒杀/复购新下单与后台业务开关更新原来使用不同读取方式：交易可能先读到“开启”，后台随后提交“关闭”，交易最后仍提交。专区新下单现与后台更新共用租户行锁；秒杀入口统一为会员→租户→活动的锁序，活动停用和库存仍由数据库条件更新复核。普通商城不占该热点锁。旧订单支付、取消、退款与奖金清算不经过新单门禁。
2. 复购区关闭、优惠券仍开时，复购专用券原可发行和新领取，却无法在关闭的专区消费。现在新发行、新领取和新单预占受关闭态门禁；目录与历史已领券显示不可用，历史记录、幂等回读和退款退券不删除，复购重新开启后按原有效期判断。公开 H5 没有复购路由，其领券中心不再提供复购专用券领取按钮；普通/复购通用券仍能在普通商城领取使用。
3. 跨商户父交易支付原按子订单生成顺序逐一锁商户；两笔交易按相反商户顺序回调时存在可推导的死锁风险。现先验证全部子单与交易号，再按商户 ID 固定顺序锁商户，最后按原子单顺序入账。该风险来自源码锁序审查，**不是已观测到的正式环境故障**。

## 仍开放的模块合同

- 余额目前没有租户级独立关闭态。关闭新提现不等于关闭新余额支付、转账或后台人工加款；旧余额、已支付余额单原路退款、奖金及资金归集不能粗暴隐藏或阻断。须先定义“停止新余额交易”与“存量资产清偿/退出”两层合同，再实现服务端/前端/财务门禁与组合回归。
- 多商户目前没有“仅平台自营”的客户级模式。隐藏商户菜单或只运营一家商户不等于关掉新开通、商品绑定、跨商户拆单与结算。未来关停只能限制新业务，历史订单退款、结算和审计仍须保持。
- 以上是 P1-16 的局部 C/T 进展，**不表示 P1-16 或全部商城收口完成**。最终统一候选须在 P0 修复/回归/同类扫描和隔离运行门禁通过后才可形成；真机及真实下单退款仍按用户安排留到最后。

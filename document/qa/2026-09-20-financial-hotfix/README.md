# 2026-09-20 财务归集、风控并发与SSE断连修复

## 根因

- 内部资金账户原来只有一份未纳入迁移总账的手工SQL，换机或重建环境不会自动执行，定时归集只能持续重试。
- 风控默认规则采用“查询不存在后新增”，并发请求可同时通过查询，再由唯一键拒绝其中一次。
- 分销模块通用异常处理器把异步响应不可写和超时当成普通500，并试图返回JSON，和SSE响应类型冲突。

## 修复

- 将系统账户脚本升级为正式第40条迁移，增加团队退出和可提现余额零值约束；标识冲突失败，重复执行幂等。
- 默认风控规则使用`INSERT IGNORE`，由`uk_rule_code`在数据库层原子去重。
- 为`AsyncRequestNotUsableException`和`AsyncRequestTimeoutException`增加专用无响应体处理，日志降为debug。

## 正式验收

- 正式库40/40、失败0；两个系统会员、推广身份、佣金账户和余额账户均各2条结构完整，所有金额合计0。
- 目标订单两条归集记录金额合计`0.01`、已结算合计`0.00`；系统资产流水0条。
- 风控规则4条且编码去重；后端1.0.152、四服务active、health UP、首页API 200。
- 从最终启动时间起，缺失归集账户、风控重复键、SSE事件流JSON写入及启动错误的日志命中0。

## 审计流程纠正

上一轮“整体检查”实际发现了这三项，但把它们作为独立问题留在报告，没有继续形成修复、验证、发布和复核闭环。今后整体检查的完成标准改为：高影响问题必须有已修复证据，或明确列为需要用户决策的阻断项；不能只写入“另外发现”后就把检查表述为完成。

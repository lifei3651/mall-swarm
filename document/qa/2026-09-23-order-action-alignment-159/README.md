## 真机失败证据

用户提供的两张微信小程序“我的订单”截图对应 **订单列表卡片，不是订单详情页**：待发货、售后处理中卡片的两个操作按钮被分到左右两边；已取消卡片仅有“再买一单”时却居中。预期为所有状态单行右下角聚拢，最右为唯一主操作，其他操作按当前顺序向左紧挨排列；单个操作也应靠右。两张原图分别为当前对话附件 `codex-clipboard-5e4f5826-2075-4342-8d58-fc298b940d83.png`（1290×2796，SHA-256 `88b322b4ae878f0186d7cf4e9f7617f36defb6e2e90330231cf7bd73f36755b4`）和 `codex-clipboard-302fe5e5-00ff-4cf2-99e8-804317496d04.png`（1290×2796，SHA-256 `22203065b576d74708c3698b1f0d86d8326431fcee4804df66df36036f4d20c7`）；含真实订单号，原图不纳入代码仓库。

这是 1.0.158 体验版的用户真机反馈，证明该布局状态**未通过**；不把此前的 CSS 静态检查写成真机通过。按商城收口规则，已上传的 1.0.158 不可原地改字节，修复源码使用新版本 1.0.159。

## 修复范围与判定边界

共用小程序普通操作按钮原有 `margin: 0`，但真机截图呈现出自动左右外边距仍参与弹性布局分配的形态。当前将原生按钮的 `margin-left/right` 明确以 `0 !important` 固定，并在同源 H5 共用样式保持同一规则；订单列表、订单详情和其他引用 `ui-action-button` 的操作组无需按状态逐页覆写。主操作仍由原有 `order: 2` 保持在最右，按钮尺寸不放大。

回归新增小程序/H5 的左右零外边距断言及共用 UI 合同门禁。定向测试、小程序全量 523 项、工程检查、H5 全量 180 项、发布脚本合同 26 项、公开/团队/一体化 H5 构建与包边界检查均通过。**这只是 1.0.159 源码和自动测试阶段**：尚未完成 1.0.159 的统一封包、独立留档、服务器/微信部署或新版本真机复核，不能表述为线上已修好。

# 1.0.155 订单列表真机反馈修复证据

日期：2026-09-21（Asia/Shanghai）

## 问题来源

用户在手机上的 `1.0.154` 订单列表发现：商品图过小，只显示商品摘要；商品名称、规格、零售价、实付款、数量和服务保障不够清楚；复制订单号不在右上角；查看物流、售后、再买一单和确认收货被拆散。用户同时提供同行页面作为信息层级参考。参考图含真实个人和订单信息，仅在本轮视觉比较中查看，没有复制进仓库。

## 修复边界

- 小程序与公开/一体化 H5 使用同一订单卡层级：标题和状态同一行、右上角复制订单号、逐商品快照、单行物流提示、件数与实付同一行、全部操作同一行且唯一主操作在最右。
- 商品图提升到小程序 `168rpx`、H5 `84px`；商品名称最多两行，规格、数量、零售价和商品实付款分别展示。
- “七天无理由”“晚发赔”等标签只读取下单时的真实商品服务标签快照。前端不硬编码标签；未配置时不显示。新订单由下单事务保存快照，历史订单由新增迁移在执行当时补一次。
- “再买一单”重新读取当前商品/SKU、库存和限购后原子加入购物车；任一商品失效时整单不写入购物车。
- 小程序“查看物流”继续使用微信官方物流查询组件；H5 保持网页物流查询入口。没有伪造物流轨迹。

## 自动与视觉验收

- 隔离 H5 实际 Vue 源码；所有接口由本地脚本拦截，没有访问或修改正式租户。
- 视口：`320×844`、`390×844`，浏览器默认 DPR 1。
- 状态：待付款、待发货、待收货、已完成双商品、已取消，共五种卡片。
- 检查：页面无横向溢出；商品图不小于 82px；名称、规格、价格和两个服务标签均落在商品区域；物流、汇总和操作保持单行；四操作不裁切；主按钮最右；按钮高度为 26–28px。

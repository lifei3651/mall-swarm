# 订单操作按钮与详情入口审查

审查日期：2026-09-13 至 2026-09-14
范围：用户提供的原生订单列表、订单详情三张截图，以及同类高频商城操作样式。

## 截图步骤

1. 用户截图一（订单详情物流区）：页面信息结构正常，但“查看物流轨迹”白底按钮与卡片背景融在一起，操作边界不清楚。
2. 用户截图二（待评价订单列表）：“查看详情”是次级动作，却与白色卡片同底；“去评价”主操作层级明确。
3. 用户截图三（已完成订单详情）：底部“查看全部订单”重复左上角返回；“客服工单”脱离统一客服入口，且与同页已有售后进度/申请售后的任务重复。

## 处理结论

- 独立次级动作统一使用浅灰底和细灰边，品牌主操作继续用红色；卡片、菜单行、输入框和状态筛选不套用这条规则。
- 原生订单详情移除常驻“客服工单”和底部“查看全部订单”，保留左上角返回、按状态出现的“申请售后”“去评价”“取消订单”“确认收货”。售后记录仍在详情内直接展示。
- H5订单操作同步；另巡检购物车管理/删除、售后数量与类型、商品评价、优惠券翻页、直播分享及工单错误重试等独立操作。

## 可访问性与证据边界

- 主次操作不再仅靠边框区分，降低低对比屏幕上误认为普通文字或空白区域的风险；原点击尺寸与文字标签保持。
- 截图来自用户本轮提供并已逐张检查。由于截图包含姓名、手机号、地址和订单号，原图不保存进代码仓库。本次证据能支持层级和重复入口判断，不能证明真机按压态、读屏顺序或弱网行为；修改后仍需微信模拟器/真机视觉复核。

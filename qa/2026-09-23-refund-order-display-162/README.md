# 1.0.162 退款订单详情显示修复（源码 / 本机自动测试）

用户在 1.0.158 体验版真机订单详情发现：同一订单的售后记录为“退款完成”，顶部却显示“已取消”；售后终态卡仍使用橙色警示底，缺失规格被拼成 `null`。真机截图含收货信息、运单与售后单号，不拷入仓库。

## 原因与边界

- 后端全额退款完成后将订单主状态置为 `4 已关闭`，保留售后状态 `1 退款完成`。原页面把所有状态 `4` 都展示为取消，且先用历史发货时间生成状态摘要，掩盖当前退款结果。
- 售后卡固定橙底，没有按九态区分进行中、完成和关闭；售后商品规格为 `null` 时，模板直接拼接原字段。
- 只根据 **订单已关闭且存在已完成的仅退款/退货退款记录** 显示“已退款”；真正取消但没有退款完成记录的订单仍显示“已取消”。不修改后端状态、退款金额、物流记录或财务账本。

## 修复与同类扫描

- 小程序订单列表、详情顶部、商品状态统一区分“已退款 / 已取消”，状态 `4` 时不再拿旧发货时间充当当前摘要；关闭状态使用共用灰色状态胶囊。
- 售后卡进行中用主题浅色，退款完成用中性浅色，拒绝/取消用灰色；空规格及字符串 `null`/`undefined` 不渲染。H5 订单列表/详情和商品规格兜底同步修正。
- 检查范围：小程序订单列表/详情、H5 订单列表/详情、售后规格格式化；未触及服务端退款状态机、金额、后台或微信物流接口。

## 验证与发布状态

- 小程序 526 项、微信工程检查通过；H5 182 项及公开/团队/一体化生产构建通过。回归覆盖退款完成与单纯取消的区分、历史发货时间不覆盖终态、`null` 规格兜底和终态卡色阶。
- 本轮只完成源码与本机自动测试；完整候选 C/T、统一封包、私有留档、服务器 S、微信 W、真机 R 均未执行。线上服务器与用户体验版仍为 `1.0.158`，不得把本修复写成已上线。`1.0.161` 在封包/分发前由本源码版取代。

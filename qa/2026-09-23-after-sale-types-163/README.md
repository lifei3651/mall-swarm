## 用户确认的范围

- 顾客和后台都不再新建“仅退款”；历史类型1保留原记录和财务追溯，不改历史数据。
- 已支付未发货、物流丢件/未收到或拒收增加独立取消/异常退款流程，不列为普通售后类型。普通售后仅保留退货退款、同规格换货。
- 原退款账务状态机继续负责支付渠道结果、库存、优惠/限购、奖金及资金冲销；**不允许仅因申请成功就提前记成退款完成**。

## 代码边界

- 小程序与 H5 依订单履约状态进入独立退款入口；未发货取消锁定全部剩余商品，物流异常只提供相应原因。登录回跳保留入口。后台“特殊退款”和取消待发货单写入内部类型4，旧客户端传类型1不再导致新建类型1。
- 顾客普通售后 HTTP 接口只接受类型2/3；独立订单异常退款接口仅接受类型4且订单路径与请求体一致。服务端核对本人、租户、订单状态、实际发货记录、剩余商品数量和退款原因；未发货取消须全量，已发货普通退货不得用异常理由绕过。
- 类型4复用售后单的审批、原渠道退款和账务流水；它只是内部记录标识，不在普通售后选择项展示。无数据库结构迁移，基础建表注释更新类型字典。历史类型1仍用于既有单据读取、金额/数量聚合和历史回归，不再由线上 HTTP 入口新建。
- 尚未进行正式环境数据写入。当前 1.0.158 体验版仍提交旧类型1，**新后端与新小程序必须作为同一验证候选协调切换**；不能单独部署服务端并把旧体验版称为可用。切换与兼容性属于下一次候选的发布门禁。

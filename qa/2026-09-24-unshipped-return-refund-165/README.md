# 1.0.165 未发货旧退货单纠错：本机验证记录

## 现象与根因

用户在现有 1.0.158 体验版对新付款但未发货订单申请“退货退款”。旧版后台审核后按实体退货流程将售后推到状态 4“待寄回”，即使订单没有发货。详情页顶部仍显示“待发货”，售后提示沉在底部且用橙色卡片，甚至对空规格拼出 `null`，误导顾客必须寄回未收到的商品。

1.0.163 已在源码中规划“未发货取消/异常退款”独立入口、禁用新建“仅退款”，但没有上线；它也不能自动处理旧版已经进入状态 4 的申请。本次补的是**旧状态纠错路径**，不恢复顾客或后台新建“仅退款”类型。

## 修复边界

- 小程序及公开 H5：进行中售后信息直接放在订单状态下面；未发货、无发货时间/运单/包裹且售后为退货退款状态 4/5 时，显示“未发货退款申请 / 待平台核实 / 无需寄回”，不显示寄回按钮、地址或旧 `nextActionHint`。其他正常退货仍按原流程。进行中卡片用主题浅色和主题色，终态沿用中性色/灰色；商品空规格不出现字面 `null`。
- 平台后台：只对订单状态 1、无任何发货记录、未提交退货物流、原售后为类型 2/状态 4 的记录显示“平台直接退款”。操作人必须核实订单、金额并填写原因；服务端以订单锁、售后锁、租户与平台账号权限、条件更新和退款历史校验复核，不允许并发发货后继续、商户操作或重复发起。
- 新入口沿用**原售后单号**及现有退款协调/账务状态机。微信/支付宝先进入状态 6“退款处理中”，只在渠道成功回执后完成净支付、奖金、资金及库存/订单结算；余额等本地支付在同一事务完成。无须虚构“已收到退货”。
- 此入口不是“任意订单强制退款”，不绕过付款、权限、金额、渠道成功或并发门禁。历史已拒绝单不会自动恢复，正式订单不会由排查脚本自动退款。

## 同类扫描与测试

- 2026-09-24 对正式库只读 SELECT：用户新售后为类型 2/状态 4，关联订单状态 1、发货时间为空、无包裹，渠道为微信；财务退款记录 0。当前同类进行中的“未发货实体退货”共 1 条，正是该例。没有读取或入仓收件姓名、电话、地址，也没有写入正式库或调用退款渠道。
- 后端回归覆盖旧状态纠错、已发货不得绕过、状态不能二次推进、原售后号与账务一次性；管理端覆盖按钮门禁及确认入口；小程序/H5覆盖顶部优先、色阶、无需寄回、旧后端误导提示隐藏及空规格兜底。
- 本机 `./mvnw -q -pl mall-distribution -am test`：792项，0失败/错误；管理端 `npm test`：219项；小程序 `npm test`：528项；H5 `npm test`：183项，均通过。后台和公开/团队/一体化 H5 构建通过；完整统一候选准入、封包和留存未执行。

## 关闭条件

先从不可变提交形成 1.0.165 唯一验证包，完成独立留档和完整准入；经分别授权后受控部署服务器、上传/切换微信体验版。平台核实该笔真实支付订单后须取得明确执行退款授权，由有权账号操作一次，并分别回读原支付渠道结果、财务退款、订单净支付/库存/奖金/资金以及顾客真机展示。余额/微信不同渠道与退货已寄出反例也需回归。没有渠道成功证据前不能声称“退款完成”，P0-14 保持开放。
